## 2. 물리 구조 (무엇이 무엇을 만드는가)

```
호흡 신경구동 ──2단 근육지연──> 폐압 Ps(t)          aeroacoustic.breath_drive
                                   │
                    ┌──────────────┴──────────────┐
                    │  직렬 유량 U (성문 + 구강)   │  aeroacoustic.series_flow
                    └──────────────┬──────────────┘
        ┌──────────────────────────┼──────────────────────────┐
        │                          │                          │
   구강 협착 난류              구강 공동 적분              성문 난류
   = 마찰음 /s/               Pm (되밀림)                = 기식
   ∝ ½ρ(U/Ac)²·게이트         oral_cavity()             aspiration_source_amp
        │                          │
        │                    (Ps − Pm) ──> 발성 역치 ──> 진동 기동 관성 ──> 유성
        │                                              (ONSET_CYCLES, 주기 수)
   앞니 다이폴 + 치찰음 극-영점 필터
```

**핵심 인과 사슬 네 개** — 이걸 깨뜨리면 소리가 무너진다.

1. **페이드는 호흡 압력에서 나온다.** 협착은 고정이다. 대칭 압력 아치로는
   정점이 49.5 % 에 남는다(진폭이 Ps 의 단조함수라 게이트·제곱법칙이 정점을
   못 옮긴다). 비대칭은 호흡 구동 자체에 있다 — 올릴 때가 내릴 때보다 느리다.
   시상수는 초가 아니라 **구간 길이 대비 비율**이다(길이가 13 배 달라도 정점
   위치가 56~57 % 로 같다).
2. **구강내압이 발성 개시를 정한다.** /s/ 동안 Pm 이 Ps 의 59 % 를 먹어
   (Ps−Pm) 이 역치에 못 미친다. 협착이 열려 Pm 이 빠져야 떨기 시작한다.
   VOT 를 손으로 박지 않는다.
3. **마찰음을 끝내는 건 혀다. 후두가 아니다.** /s/ 는 성문을 벌린 채 내는
   소리다.
4. **마찰음과 목소리를 잇는 건 기식이다.** 마찰음 꼬리가 아니다.

## 4. 다음 할 일 — **앞니 다이폴이 /s/ 개시부터 있어야 한다** (사용자 지적, 최우선)

### 증상

사용자: "앞니 다이폴은 처음 's' 의 조음 시작과 동시에 있어야 하는데."

### 측정 (확인됨)

`_scale_sib_center()` 가 무게중심 배율 `cent` 를 `pole_f`, `zero_f`,
**`teeth_f` 에까지** 곱한다. `cent` 는 입자속도에서 나오는데, /s/ 개시에는
압력이 낮아 속도가 느리므로 배율이 작다. 그래서:

```
 t(ms)  마찰음   무게중심배율   앞니 공명이 실제로 놓이는 자리
     0   0.104      0.620          6214 Hz     <- 지문은 10015 Hz
    20   0.469      0.831          8326 Hz
    50   0.815      0.951          9520 Hz
   100   1.000      1.000         10015 Hz     <- 여기서야 제자리
```

**개시 순간 앞니 공명이 3.8 kHz 아래에 있다.** 6214 Hz 는 /ʃ/ 영역이다.
즉 /s/ 가 /ʃ/ 로 시작해서 /s/ 로 변해간다.

### 진단

**소스와 필터를 뒤섞고 있다.**

- Stevens(1971) 가 말하는 건 **난류 소스** 스펙트럼의 무게중심이 입자속도와
  함께 오른다는 것이다.
- 그런데 우리는 그 배율을 **성도 쪽 공진 주파수**(앞공동 극, 앞니 공명)에
  곱하고 있다. 앞니 공명은 혀끝-앞니 간극이 정하는 **기하학**이다. 기류가
  느리다고 앞니가 멀어지지 않는다.
- 특히 지금은 페이드 인 구간에서 **협착 면적이 고정**이다(우리가 그렇게
  만들었다). 기하가 안 변하는데 공진만 움직이는 건 자기모순이다.

협착이 **열릴 때**(해제) 앞공동 기하가 실제로 바뀌므로 그때 극이 움직이는 건
맞다. 문제는 기하가 안 변하는 페이드 인 구간이다.

### 제안하는 수정

`cent` 를 **소스 쪽**(난류 대역 게인의 기울기)에 걸고, 치찰음 필터의 공진
주파수는 **협착 면적**에서 유도한다. 최소 수정으로는 `teeth_f` 를 스케일
대상에서 빼는 것만으로도 개시가 크게 나아질 것이다(순수 기하이므로).

```python
# score.py:232  _scale_sib_center
#   현재: for k in ("pole_f", "zero_f", "teeth_f")
#   제안: 앞니 공명은 기하 -> 빼고, 앞공동 극은 면적 궤적에서 유도
```

### 주의 — 이걸 건드리면 같이 흔들리는 것

1. `SYLLABLE_FRICATIVE_CAL_DB`. 지난번에 봉우리를 8.4 → 10.0 kHz 로 올렸을 때
   그 자리가 앞니 다이폴 부스트가 제일 큰 자리(`f_max_boost` 11 kHz)여서
   /s/ 가 통째로 세졌고, **모음−마찰음이 21 dB 어긋났다**. 봉우리를 건드리면
   반드시 §6 의 레벨 측정을 다시 돌려라.
2. `test_aeroacoustic.py::test_centroid_descends_from_constriction_area_alone`.
   무게중심 하강을 검사한다. 소스 쪽으로 옮기면 이 테스트가 재는 대상이

   재는지 바꿔야 한다).

## 5. 알려진 결함 (고치지 않고 남겨둔 것)

### (a) 음절 레벨 보정 상수가 프로파일마다 15 dB 다르다

`SYLLABLE_FRICATIVE_CAL_DB = 25.0` 은 `me.json` 기준이다. 기본 프로파일에
쓰면 15 dB 어긋난다.

**원인**: 마찰음 세기를 **소스 진폭**(`harmonic_amp`)으로 기준화하는데, 유성음의
실제 세기에는 성도 캐스케이드 이득이 곱해져 있다. 마찰음은 그 캐스케이드를
우회하므로(`noise_entry = K+6`) 화자마다 캐스케이드 이득만큼 어긋난다.

**제대로 된 해법**: 기준을 소스가 아니라 **렌더된 모음 세기**로 옮긴다.

> 한 번 시도했다가 되돌렸다. 다이폴을 RMS 정규화하고 캐스케이드 이득을 곱해
> 봤는데, 프로파일 의존은 안 사라지고(/s/ 구간이 기식 지배로 넘어가면서)
> `FRICATIVE_CAL_DB` 까지 줄줄이 흔들렸다. 손대려면 §6 측정 도구를 먼저 갖추고
> 한 번에 끝내라.

### (b) 추출기의 tilt 가 재현되지 않는다

`analysis/extract.fit_source_rd_tilt` 가 낸 `tilt=+8.747` 로 합성하면 1~2 kHz 가
에너지의 36.8 % 가 된다(실측 4.2 %). 합성기는 tilt 를 **H1 기준** 옥타브당 dB 로
가산하는데(`dsp/glottal.py:184`), F0=124 Hz 면 1~2 kHz 가 +29 dB 부풀기 때문이다.
닫힌고리로 다시 맞춘 값 −1.0 을 `profiles/me.json` 에 넣고, 경위를
`meta.tilt_refit` 에 적어 뒀다. **추출기 자체는 아직 안 고쳤다.**

### (c) 모음 4~6 kHz 가 조금 세다

3.3 % vs 실측 2.1 %. 상대 고역비(0.41 vs 0.42)는 맞아서 그대로 뒀다.

### (d) 독립 마찰음의 가청 길이는 세그먼트의 약 48 %

나머지는 압력이 임계 유속에 못 미쳐 소리가 안 나는 앞뒤 램프다(그게 페이드의
실체다). 1.1 s 짜리 /s/ 를 들으려면 `dur` 을 2.3 s 로 잡아야 한다
(`scripts/gen_me_sibilant.py` 의 `AUDIBLE_FRAC`).

## 6. 측정 도구 — **작업 전후로 반드시 돌려라**

귀가 없으므로 이게 유일한 판단 근거다. 아래를 `/tmp` 스크립트로 만들어 쓴다.

### 포락선 모양 (페이드 인 비율, 상승/하강비)

```python
win, hop = 1024, 256
f = torch.linspace(0, fs/2, win//2+1)
S = torch.stft(x, win, hop, window=torch.hann_window(win), return_complex=True).abs()
hi = (S[f > 4000]**2).sum(0).sqrt(); hi /= hi.max()      # 마찰음 포락선
lo = (S[(f > 200) & (f < 1000)]**2).sum(0).sqrt(); lo /= lo.max()   # 유성
pk = hi.argmax(); on = (hi > 0.1*hi.max()).argmax()
# 음절이면 off = 유성이 0.5 를 넘는 첫 프레임, 아니면 마지막 0.1 교차점
frac = (pk - on) / (off - on)       # 페이드인 비율. 목표 0.52~0.63
```

### 치찰음 봉우리 / 대역 분포

정점 근처 몇 프레임의 평균 스펙트럼에서 1.5~12 kHz 최댓값 위치. 목표 ~9.9 kHz.
대역별 에너지 비율도 같이 본다.

### 모음−마찰음 세기 (이게 제일 잘 드리프트한다)

```python
L = lambda a, b: 20*log10(rms(x[int(a*fs):int(b*fs)]))
L(0.30, 0.57) - L(0.03, 0.11)     # m01_sa.wav 기준. 목표 +11 dB
```

### 전이가 비지 않는지

`hi` 포락선이 마찰음 끝~발성 사이에서 얼마까지 떨어지는가. 목표 ≥ 0.13.
0 에 가까우면 성문파열음으로 들린다.

### 제어 신호 직접 보기 (원인 추적용)

```python
c = build_segment({...}, prof, cfg)
c["noise_bands"].sum(-1)      # 마찰음
c["aspiration_bands"].sum(-1) # 기식
```

## 7. 지뢰밭 — 겪은 것들

- **`transition_s` 하나가 세 조음기관을 끌고 있었다.** 지금은 혀끝
  `release_s`, 후두 `adduction_s`, 혀몸 `transition_s` 로 분리돼 있다.
  다시 합치지 마라.
- **포먼트 전이를 발성 개시에 묶으면 안 된다.** 후두 타이밍을 건드릴 때마다
  포먼트가 딸려 오고 "사" 가 "야" 로 들린다. 지금은 **협착 해제 시점** 기준이다.
- **내전을 마찰음 중간에 시작하면 /s/ 가 죽는다.** 성문이 좁아지면 직렬 저항의
  무게중심이 성문으로 옮겨가 협착 뒤 압력이 무너진다(Ac 는 그대로인데
  마찰음이 0.79 → 0.18). 겹침을 늘리고 싶어도 여기를 당기지 마라.
- **기식을 `(1-v_frac)` 로 끄면 성문파열음이 된다.** 발성은 난류를 없애지
  않는다. 다만 **전이 기식**은 발성에 반비례하고 **기식성 바닥**은 발성에
  비례한다 — 둘은 별개다.
- **정적 성문 면적은 주기적 완전폐쇄를 표현 못 한다.** 성문 제트속도는
  `v=sqrt(2Ps/ρ)` 로 압력만이 정해서, 성문을 0.004 cm² 까지 조여도 기식
  진폭이 /s/ 때와 거의 같다. 그 몫을 발성 비율로 대신 주고 있다.
- **레벨/질감 통계는 고원부에서 재라.** 전체 RMS 로 재면 페이드 모양이 레벨에
  섞여서, 페이드를 만질 때마다 음량이 따라 움직인다.
- **테스트 임계값을 낮춰서 통과시키지 마라.** 두 번 낮춘 적이 있는데 둘 다
  "무엇을 재는지" 가 바뀌었기 때문이고, 그 이유를 테스트 안에 적어 뒀다.
  이유를 못 적겠으면 그건 회귀다.
- **`test_voice.py` 의 `PROF` 는 기본 프로파일이다.** 화자 프로파일로 재야 하는
  검사는 `_me_profile()` 을 쓴다.

## 8. 계정 두 개로 병렬 작업할 때

실제로 두 세션이 같은 파일을 동시에 고친 적이 있고, 한 번은 같은 문제
(마찰음 페이드)를 서로 다른 방법으로 고쳐서 충돌했다(`6d2dc73` 병합).

- **push 전에 항상 `git fetch origin main` 하고 확인한다.**
- `git merge-base --is-ancestor origin/main <branch>` 로 fast-forward 가능
  여부를 먼저 본다.
- **force-push 금지.** 상대 세션의 커밋을 지운다. 충돌하면 병합하고, 어느
  쪽을 택했는지 커밋 메시지에 남긴다.
- 상대가 이미 고친 것을 다시 고치지 말고, 근거(측정값)가 있는 쪽을 택한다.
  실제로 저쪽이 실측 LPC 로 F1/F2 전이 속도를 바로잡은 적이 있다(`b86f2a4`).
- `claude/voice-generation-physics-model-kuty1l` 브랜치는 별개의 실험 라인이다.
  건드리지 않는다.
