## 1. 이번 세션에서 해결된 것

### 위상 붕괴의 원인은 최적화 예산 부족이었다

동적 구간의 위상 오차가 무상관 수준(77~96°)이던 문제. 원인은 물리도 구조도 아니고
**위상 단계를 충분히 안 돌린 것**이었다. 단계별로 재 보면 크기 적합 단계는 설측의
위상을 아예 못 건드리고(초기 94.8° → 격자 1 ms 96.5°) 오직 위상 단계만 움직이는데,
그 단계의 lr 이 0.016 이고 반복이 200 이었다. 설측 기준 lr 이 7 배 작았다.

고친 것: `pick_lr_phase` (후보 0.05/0.12/0.25 중 짧은 탐침으로 선택) + `phase_iters=800`.

벤치 결과 (`scripts/bench_copyfit.py`):

| 구간 | 위상 | 이전 | 개선 |
|---|---|---|---|
| 여 긴 /아/ | 0.5° | 3.4° | 6.8× |
| 여 ㅆ+이 (씨) | 17.6° | 61~82° | 3.5~4.6× |
| 여 설측 (닐) | 33.8° | 77.3° | 2.3× |
| 여 탄음 (이리) | 25.4° | 55.3° | 2.2× |

0.3.5 의 쌍봉 분포에서 무상관에 가깝던 절반(41~90°)이 사라졌다.

### relu 를 걷어내 손실을 C² 로 만들었다

사용자 지시이자 실질적 이득이었다. 벌점 넷과 손실 본체 셋에서 제거:

```
torch.relu            -> _soft_over    = width·softplus(x/width)
torch.where(후버)     -> _pseudo_huber = √(1+r²)−1
.clamp_min(db_floor)  -> _soft_floor
(a−b).abs() 포락 L1   -> _soft_abs
(St−Sp).abs() 위상    -> √(|z|²+δ²)−δ
```

**시프트는 넣지 않았다.** ssp(x)=ln(1+eˣ)−ln2 는 활성함수용이고(ssp(0)=0), 단측 벌점에
쓰면 x→−∞ 에서 −ln2 로 수렴해 제약을 잘 지킬수록 벌점이 음수가 된다. 엔진에 relu 를
활성함수로 쓰는 곳은 없다.

효과 — 유한차분 헤시안의 대칭성이 되살아났다:

| ε | 이전 (relu) | 현재 |
|---|---|---|
| ~7e-04 | 41.9 % | **3.0 %** (모음) / **1.9 %** (탄음) |
| ~7e-05 | 47.5 % | 7.6 % / 3.2 % |
| ~7e-06 | 178.2 % | 12.5 % / 9.5 % |

이전에는 **어느 ε 에서도** 개선되지 않았다(구조적). 지금은 ε 을 키우면 좋아지는
정상적인 수치미분 거동이다. 손실값 변화는 0.74 % 뿐이다.

## 4. 진행 중이던 것

### 가속도(2 차 차분) 벌점 — 유일하게 성공한 방향

`VEL_MODE="accel"`, 무릎은 실측 중앙값 (F1 0.7 / F2 1.9 / F3 3.4 / F4 3.5 Hz/ms²).

크기가 아니라 **시간 구조**로 가른다. 난동은 부호가 매 프레임 뒤집혀 가속도가 크고,
실제 급전은 한 방향으로 지속돼 가속도가 작다. 판별 여유가 속도보다 7 배 넓다:

```
속도로   실제 7.0 vs 난동 ~300  ->  43 배
가속도로 실제 1.9 vs 난동 ~600  -> 300 배
```

정상 모음 결과 — **네 지표가 전부 동시에 좋아진 유일한 방법이다**:

| VEL_W | 위상 | 조화 SNR | F2 가속 | 비조화 합/목 |
|---|---|---|---|---|
| 0.000 | 4.3° | 14.57 | 110.3 | 0.6 / 0.5 % |
| 0.003 | 2.6° | 25.79 | 1.2 | 0.5 / 0.5 % |
| 0.010 | 2.6° | 26.60 | 1.1 | 0.5 / 0.5 % |

**씨 구간에서도 성립한다 — 동적 구간에서 네 지표가 동시에 좋아진 첫 사례:**

| VEL_W | 위상 | 조화 SNR | F1 속도 (실측 1.9) | F2 속도 (실측 15.6) | F2 가속 | 비조화 합/목 |
|---|---|---|---|---|---|---|
| 0.000 | 17.6° | 10.30 | 156.3 | 525.6 | 792.6 | 1.4 / 0.9 % |
| 0.001 | **12.1°** | 11.23 | 12.2 | 37.6 | 1.5 | 1.2 / 0.9 % |
| 0.003 | **12.1°** | 10.77 | 5.6 | **13.1** | 1.2 | **0.9 / 0.9 %** |

위상 1.5 배 개선, F2 속도 40 배 개선(실측 15.6 에 거의 일치), 비조화가 목표와 정확히
일치. 같은 구간에서 속도 후버와 성긴 격자는 둘 다 위상을 악화시켰다.

**이것이 #15(비조화 잔차 초과)의 답이기도 하다.** 원인 미상으로 남겼던 항목인데,
궤적을 *올바른 방식으로* 잡으니 목표값과 일치한다. 앞서 속도 사전으로 눌렀을 때
오히려 늘었던 것은 그 방법이 실제 조음까지 죽여 다른 식으로 신호를 망가뜨렸기
때문이다.

**설측에서도 성립한다 — 다만 세기에 훨씬 민감하다:**

| VEL_W | 위상 | 조화 SNR | F1 속도 (4.1) | F2 속도 (26.5) | F2 가속 | 비조화 합/목 |
|---|---|---|---|---|---|---|
| 0.000 | 33.8° | 9.14 | 125.2 | 396.3 | 785.6 | 2.7 / 1.6 % |
| **0.001** | **32.4°** | **9.99** | **8.9** | **32.8** | 2.6 | 2.8 / 1.6 % |
| 0.003 | 53.8° | 5.51 | 5.2 | 15.9 | 1.5 | 2.6 / 1.6 % |
| 0.010 | 66.0° | 5.83 | 4.7 | 10.3 | 1.1 | 2.1 / 1.6 % |

0.001 에서 F2 속도가 396.3 → 32.8 로 실측 26.5 에 붙으면서 위상·SNR 이 **오히려
좋아진다.** 속도 후버(1.4~1.9 배 악화)와 성긴 격자(2.4 배 악화)가 둘 다 무너진
구간이다.

0.003 이상에서 무너지는데, 그 지점에서 F2 속도가 15.9 로 **실측 26.5 보다 느려진다.**
앞선 모든 실패와 같은 신호다 — 실제 조음보다 느리게 만들면 파형이 망가진다.

### 세 구간 종합 — 최적 세기가 구간마다 다르다

| 구간 | 실측 F2 속도 | 최적 VEL_W | 그 값에서 |
|---|---|---|---|
| 긴 /아/ | 1.9 | 0.010 | 4.3 → 2.6°, SNR +12.0 dB |
| 씨 | 15.6 | 0.003 | 17.6 → 12.1° |
| 설측 | 26.5 | **0.001** | 33.8 → 32.4° |

**실제 조음이 빠른 구간일수록 약한 벌점이 필요하다.** 규칙적이므로 우연이 아니고
물리적으로도 당연하다 — 빠른 조음은 가속도도 크다.

원인은 **무릎을 전역 중앙값 하나(F2 1.9 Hz/ms)로 고정한 것**이다. 설측의 실제
가속도는 그보다 크니 무릎이 너무 낮고, 조금만 세게 걸어도 실제 조음을 누른다.

### 지금 켠다면

**`VEL_W = 0.001`.** 세 구간 전부에서 무제약보다 낫고(모음 4.3→3.7°, 씨 17.6→12.1°,
설측 33.8→32.4°) 어디서도 무너지지 않는다. 다만 모음에서 얻을 수 있는 것
(0.010 에서 2.6° / +12 dB)을 다 못 가져온다. **기본값은 아직 0 이다** — 켜는 것은

### 유효 파라미터 수 γ

두 경로가 있고 둘 다 검증을 통과한다.

**야코비안 (JᵀJ, 손실과 무관하게 모형의 식별가능성)** — 정상 모음 N=3840:

| α (잔차 대비) | γ | γ/N |
|---|---|---|
| ×0.1 | 647.0 | 16.8 % |
| **×1 (= 잔차)** | **316.4** | **8.2 %** |
| ×10 | 109.0 | 2.8 % |

검증: 비대칭도 1.5 %, vᵀAv > 0, 스펙트럼 음수 비중 0.00 % (JᵀJ 은 반정부호라
음수가 나오면 그 자체가 잡음의 증거 — 헤시안 경로에 없던 내장 검증).

읽는 법: 제어 파라미터 32 개이므로 316/32 ≈ **10 개 시간점**, 200 ms 구간이니
**약 20 ms 마다 제어점 하나**. 조음의 시간척도와 일치하고, 격자 실험에서 10 ms 가
궤적을 가장 물리적으로 만든 것과도 맞는다.

**동적 구간은 검증에 실패했다 — 값을 쓰면 안 된다.**

| 구간 | 음수 고윳값 비중 | 판정 |
|---|---|---|
| 정상 모음 | 0.00 % | 유효 (γ = 316) |
| 탄음 이리 | 27.81 % | **무효** |
| 설측 닐 | 67.37 % | **무효** |

JᵀJ 은 반정부호라 음수가 나올 수 없다. 나왔다는 것은 수치 잡음이다. 탄음 710.9,
설측 901.7 같은 값은 인용하지 말 것.

**교훈: 대칭성 검사만으로는 부족하다.** 설측은 비대칭도 0.9 % 로 통과했는데 스펙트럼
음수 비중이 67 % 였다. 벡터 한 쌍의 대칭성과 스펙트럼 전체는 다른 것을 본다.
반드시 둘 다 볼 것.

**다음 시도:** 엔진이 파형을 float32 로 내보내는 것이 원인으로 보인다. 동적 구간은
필터가 빠르게 변해 파형 응답의 비선형성이 크고, 같은 ε 에서 중심차분 정확도가 더
나쁘다. `VoiceEngine.forward` 가 `dt_in`(float32)로 캐스팅해 돌려주는 것을 float64 로
바꾸거나, ε 을 더 키워서(1e-3 이상) 다시 재 볼 것.

## 5. 남은 문제

* **적합 궤적이 비물리적** (#16). 위상을 고쳐도 그대로다 — 씨 구간은 위상 17.6° 로
  잘 맞는데 F2 속도가 실측 15.6 의 34 배(525.6)다. 이게 풀려야 다음 단계인
  "적합 트랙에서 제스처·프로파일 역보정" 으로 갈 수 있다. 가속도 벌점이 유일한 후보.
* **비조화 잔차 초과** (#15). 설측 2.7 vs 1.6 %, 탄음 8.4 vs 5.2 %. 모음은 일치.
  설명 둘(잡음 과다, 궤적 난동)이 기각됐다. 다만 가속도 벌점을 걸면 모음에서
  0.6 → 0.5 % 로 목표와 정확히 일치하게 되므로, 동적 구간에서도 그런지 봐야 한다.
* **적합 시간.** 예산을 늘린 대가로 구간당 5 → 25 분이 됐다. 코퍼스 규모로 가려면
  수렴 판정을 붙여 필요한 만큼만 돌려야 한다. 지금 `fit()` 은 고정 반복 후 최저손실
  스냅샷을 취할 뿐 수렴 판정이 없다.

### 가장 큰 약점: 표본이 파일 하나다

**이번 세션의 결론은 전부 `data/ref/female_yang_ilin-ilsil.wav` 의 네 구간에서만
확인했다.** `data/voices/` 의 코퍼스 25 개는 세션 전반부(12 구간 분포, 눌린 발성
H1−H2 조사)에만 쓰였고 지금 결론들의 검증에는 안 쓰였다. 다음 세션의 우선 항목은
**코퍼스로 일반성 확인**이다 — 특히 위상 예산 수정과 가속도 벌점이 다른 발화에서도
같은 효과를 내는지.

## 6. 도구

* `scripts/bench_copyfit.py` — 고정 구간 회귀 벤치. 위상·조화 SNR·궤적 속도·비조화를

* `out/listen/` — 목표·합성 대조 wav (예산 수정 **전** 적합).
* `out/diag/*.npz` — 적합 결과 캐시 (목표·합성 파형, f0, 유성, 포먼트 트랙).

## 7. 치찰음의 "지글거림" — 소스가 아니라 필터다

사용자가 청취에서 "우리 쪽이 백색잡음 같지 않고 더 지글거린다" 고 지적했다.

### 자를 어떻게 세우는가

지글거림은 크기 스펙트럼이 아니라 **시간 구조**다. 고역(4~12 kHz) 포락의 **변조
스펙트럼**으로 본다. 그리고 **대조군이 반드시 필요하다** — 순수 가우시안 대역잡음도
800~2000 Hz 변조 대역에 62 % 를 갖는다. 기준선 없이 보면 정상을 결함으로 오독한다
(실제로 한 번 오독했다가 철회했다).

| | 변조깊이 | 첨도 | 5~60 | 60~400 | 400~800 | 800~1200 | 1200~2000 |
|---|---|---|---|---|---|---|---|
| 가우시안 대역잡음 (이상적) | 0.53 | 2.96 | 1.2 % | 18.4 % | 18.4 % | 19.2 % | 42.8 % |
| + 느린 변조 (제트 사행) | 0.56 | 3.37 | 15.7 % | 23.7 % | 20.8 % | 13.1 % | 26.7 % |
| + 사각파 게이트 | 0.61 | 3.59 | 0.7 % | 47.2 % | 19.6 % | 13.1 % | 19.5 % |
| **우리 마찰 소스** | **0.54** | **3.25** | 8.4 % | 25.9 % | 20.6 % | 19.9 % | 25.2 % |

### 결론: 마찰 소스는 정상이다

이상적 가우시안 난류와 사실상 구분이 안 된다. 5~60 Hz 가 8.4 % 로 높은 것은 의도한
제트 사행이다. **`noise.py` 는 건드릴 필요가 없다.**

### 원인은 복사합성 적합의 궤적 난동이다

적합 결과 세 구간 모두 같은 방향이다 — 목표는 느린 변조에 몰려 있고 우리는
중·고속으로 퍼진다:

| 4~12 kHz 포락 변조 | 5~60 Hz | 60~400 | 400~800 | 800~1200 | 1200~2000 |
|---|---|---|---|---|---|
| 모음 목표 | 2.5 % | 38.9 % | 19.1 % | **16.6 %** | 22.9 % |
| 모음 합성 | 2.0 % | 18.7 % | 28.0 % | **35.8 %** | 15.6 % |
| 설측 목표 | 58.7 % | 7.6 % | 13.7 % | **13.4 %** | 6.5 % |
| 설측 합성 | 36.7 % | 17.5 % | 16.6 % | **19.7 %** | 9.5 % |
| 탄음 목표 | 77.8 % | 7.7 % | 7.2 % | **4.1 %** | 3.2 % |
| 탄음 합성 | 62.9 % | 13.9 % | 10.1 % | **6.1 %** | 7.1 % |

초과가 가장 큰 것이 모음(800~1200 Hz 에서 2.2 배)인데 **모음이 궤적 난동도 가장
심하다**(F1 284 Hz/ms). 공진기가 1 kHz 속도로 흔들리는 필터에 잡음을 통과시키면
정확히 이 질감이 나온다. 소스는 깨끗한데 **필터가 잡음을 변조하는 것**이다.

즉 별개 과제가 아니라 **#16 궤적 난동의 청각적 증상**이다. 가속도 벌점이 궤적을
잡으면 같이 해결될 것으로 예상하고, 위 자(`scripts/probe_texture.py`)로 검증한다.
스크립트 렌더(`out/ab_male/sa_B_syn.wav`)는 제어 트랙이 매끄러워 이 초과가 없다는
것이 방증이다.

### 부수적으로 발견한 것 — 사각파 게이트

`noise.py` 의 `am = 1 − 0.5·voiced·(frac < 0.35)` 는 성문 주기의 앞 35 % 동안 마찰
진폭을 절반으로 뚝 떨어뜨렸다 올리는 **샘플 해상도의 계단**이다. 위 표에서 보듯
60~400 Hz 변조를 47.2 % 까지 끌어올린다(대조군 18.4 %). 무성 치찰음에서는
`voiced=0` 이라 비활성이지만 유성 마찰(/z/ 계열, 모음 속 기식)에서는 작동한다.
실제 성문-마찰 결합은 매끄러운 유량 변조지 계단이 아니다. `(frac < 0.35)` 는 또 하나의
꺾임이기도 하다 (§ relu 제거와 같은 부류). 아직 안 고쳤다.

## 8. 치찰음의 자를 바꿨다 (2026-09-08 후속 세션)

`docs/MEASUREMENTS.md` §9 에 수치와 대조군이 있다. 여기는 판단이다.

### 8.1 지금까지 치찰음을 **못 재고 있었다**

`정밀 일치`(선형 다해상도 STFT 수렴도)는 난류에서 **34.5 % 가 원리적 상한**이다.
같은 스펙트럼의 두 독립 실현을 서로 채점하면 33.3 % 가 나오고, 이론값(레일리 크기,
√((4−π)/2))과 일치한다.

**그러므로:**

* "정밀 88 %" 는 나쁜 값이 **아니었다.** 치찰음이 든 구간에서는 자가 바닥에 눌린 것이다.
* 치찰음 구간에 "95 %" 를 목표로 거는 것은 달성 불가능한 목표가 아니라 **틀린 자**다.
* 과거 기록에서 마찰이 든 구간의 `정밀` 값을 모형 품질로 인용하지 말 것.

대신 `fit.fidelity()` 의 `fine_corr` 을 쓴다. 같은 파라미터를 **시드만 바꿔** 한 번
더 합성해 실현 잡음의 바닥을 재고 제곱 영역에서 뺀다. 완벽한 모형에서 97.2 % 로
수렴하고, 하모닉에서는 값을 바꾸지 않는다(100 → 100).

같이 나오는 `floor` 가 **그 구간에서 기존 자의 상한**이다. `fine` 이 `floor` 근처면
모형이 아니라 자를 보고 있는 것이다.

### 8.2 위상 항이 마찰음을 끄고 있었다 — 있던 버그

`|S_t − S_p|` 는 위상이 무상관인 곳에서 **|S_p| = 0 이 최소**다
(E|S_t−S_p|² = |S_t|²+|S_p|²). 실측으로 g 를 훑으면 g=0 에서 0.999, g=1 에서 1.411 이다.

`fit_staged` 는 이 항을 **기본 800 회** 돌린다. 즉 §1 에서 "위상 예산이 모자랐다"
고 늘린 그 예산이, 마찰 구간에서는 소리를 끄는 방향으로 800 회 쓰였다. §1 의 위상
개선 수치(설측 2.3 배 등)는 유성 구간의 값이므로 유효하지만, **같은 변경이 마찰
구간에는 해로웠다.**

고친 형태는 단위 크기 복소 잔차를 목표 크기로 가중한 것이다 — 크기에 대한 편미분이
항등적으로 0 이다. 가중은 목표의 조화 우세도라 난류 빈은 아예 안 본다.

### 8.3 A/B 로 확인했다 — 셋 다 성립한다

같은 코퍼스 구간을 예전 코드(`old`)와 새 코드(`both`)로 각각 적합했다
(예산 60/40/250, lr 고정, patience 25):

| 구간 | 모드 | 포락 | 무게중심 오차 | 대역 MAE | 시머 | **합성/목표 rms** | 시간평균 스펙트럼 |
|---|---|---|---|---|---|---|---|
| 치찰 ㅅ | old | 83.61 | **−732 Hz** | 1.72 | 0.076 | **0.900** | 53.35 |
| 치찰 ㅅ | **new** | **90.51** | **0 Hz** | **0.23** | **0.031** | **0.984** | **61.73** |
| 치찰+모음 | old | 62.70 | −437 Hz | 1.22 | 0.030 | **0.773** | 48.73 |
| 치찰+모음 | **new** | **78.89** | +85 Hz | **0.46** | 0.030 | **0.980** | **59.17** |
| 모음 | old | 94.90 | −1 | 2.11 | 0.015 | 0.999 | 74.76 |
| 모음 | **new** | **95.90** | −0 | 2.03 | 0.017 | 1.000 | **76.59** |

1. **마찰 대역 에너지가 회복된다.** 합성/목표 rms 가 0.773 → 0.980, 0.900 → 0.984.
   위상 항이 소리를 끄고 있었다는 예측 그대로다.
2. **지터·시머로 흉내내던 것이 줄었다.** 치찰 ㅅ 의 시머 0.076 → 0.031.
3. **포락은 안 깎였다 — 오히려 올랐다.** 치찰+모음 +16.2 %p, 치찰 ㅅ +6.9 %p,
   모음 +1.0 %p. 동적 구간일수록 이득이 크다.

덤으로 **무게중심 오차가 −732 → 0 Hz** 다. /s/ 가 /ʃ/ 쪽으로 밀려 있던 것이 제자리를
찾았다는 뜻이고, 이게 "치찰음이 안 맞는다" 는 청취 인상의 정체였을 가능성이 높다.

### 8.3b 그 A/B 가 **자의 결함도** 드러냈다

치찰음 구간 넷에서 `보정정밀 100.00` 이 나왔다. 완벽해서가 아니라 합성의 실현 분산이
목표보다 커서 D_pp' 를 통째로 뺀 것이 과했다 — 녹음은 위너 차감을 거쳐 스펙트럼이
평활해져 있으므로 V_t < V_p 가 오히려 정상이다.

고쳤다 (V_t 를 따로 추정하고 합성 쪽 참값으로 눈금 교정). 그래도 **편향이 실현 잡음보다
작으면 원리적으로 분해가 안 된다.** 그때의 값은 상한이므로 `>=` 로 표시하고,
완벽한 모형과 잡음 과다를 가르는 것은 `noise_ratio` 다 (ADR 0013).

**교훈: 새 자를 만들면 실제 구간에서 끝까지 돌려 봐야 한다.** 합성 대조군에서는
멀쩡했고 (완벽 97.2 %), 실제 적합 결과에서만 무너졌다.

### 8.4 코퍼스로 옮겼다

`bench_copyfit.py` 의 네 구간은 레포에 없는 파일을 가리킨다. `scripts/bench_corpus.py`
가 orphan 코퍼스의 고정 구간 넷을 쓴다.

구간을 고르며 알게 된 것: **고역/저역비만으로는 치찰음과 호흡·기식이 안 갈린다.**
그것만 쓰면 무게중심 중앙값이 5175 Hz (프로파일 실측 8100 Hz). 치찰도 > 8 dB 이고
무게중심 > 6 kHz 로 거르면 7997 Hz 로 맞는다. `analyze.py` 의 `fric` 마스크도 같은
문제를 갖고 있다 — 그 마스크는 `tract_gain` 을 1.0 으로 고정하고 `fric_gain` 보정에
쓰이므로, 호흡을 마찰로 보면 초기값이 틀어진다. **아직 안 고쳤다.**

### 8.5 그 밖에 고친 것

* `pyproject.toml` 이 0 바이트였다 (0.3.1 커밋에서 잘림). 설치가 통째로 안 됐다.
* `VoiceEngine.reset()` 이 `NoiseBank(cfg.seed)` 로 덮어써서 `eng.noise` 대입이
  조용히 무시된다. 시드를 바꾸려면 `cfg.seed` 를 통해야 한다.
* `noise.py` 의 사각파 게이트를 올림 코사인으로 (§7 이 남긴 숙제). 주기 평균 0.8250 은

### 9.0a 긴 음원 적합 트랙의 파라미터 분포 (yang_00000101, 1.42 s)

| 파라미터 | 최소 | 25 % | 중앙 | 75 % | 최대 |

실제로 눈에 띄는 것은 `fric_gain` 이다. 중앙 10.18, 최대 67.26 — 초기값 1.0 에서
한 자릿수 이상 올라갔다. `calibrate_gain` 이 무성 프레임에서 닫힌 형태로 주는 값이
출발점이므로, 그 값 자체가 크다는 뜻이거나 프레임별 적합이 더 올린 것이다.

`p_sub` 중앙 6.33 은 정상 범위다 (§9.1b 의 12~16 cmH₂O 는 짧은 구간에서만 나왔다 —
긴 음원에서는 전역 이득이 제대로 잡히므로 그 항목은 예산·구간 길이 문제일 수 있다).

### 9.0-1 비조화 초과 — 원인을 좁혔다 (MEASUREMENTS §11)

`scripts/probe_nonharmonic.py` 로 적합 트랙에서 한 번에 하나씩 끄고 다시 렌더했다
(yang_00000101 전체 1.42 s, 목표 대조군 포함).

**기각된 가설 둘 — 다시 시도하지 말 것:**

* **지터·시머** — 끄면 오히려 올라간다 (2.0 → 2.7 / 2.8 %). 그 둘이 목표의 비주기성
  일부를 실제로 설명하고 있었다.
* **계수 변조(궤적 난동)** — 트랙을 뭉갤수록 단조롭게 악화된다

**다만 이 음원에서는 초과 자체가 작다** (전체 2.0 vs 목표 1.2 %). §9.12 의 짧은 구간에서
42.8 vs 25.2 % 였던 것과 규모가 다르므로, 구간 길이·경계 효과가 그 값에 섞였을
가능성을 배제하지 못한다. §10.1 이 경고한 대로 이 잔차는 **목표 유성 프레임**에서만
잰 것이고 순수 무성 정상부가 아니다.

### 9.0 치찰음 구간의 비조화 초과 (원래 관찰 — 위에서 좁혀졌다)

회귀 벤치 (§9.12) 에서 유일하게 크게 벌어진 지표다:

| 구간 | 합성 | 목표 | 비 |
|---|---|---|---|
| 치찰 ㅅ | 42.8 % | 25.2 % | 1.7× |
| 치찰 ㅆ | 25.8 % | 8.8 % | 2.9× |
| 치찰+모음 | 40.7 % | 9.6 % | **4.2×** |
| 모음 | 0.8 % | 0.8 % | 1.0× |

**모음에서는 완전히 사라졌다.** 즉 §4 의 "가속도 벌점이 #15 의 답" 이라는 관찰이
정상 구간에서는 맞았고, 마찰이 든 구간에는 다른 원인이 남아 있다.

같은 구간의 위상(59.6° / 66.2°)과 음수 조화 SNR 을 **먼저 논하지 말 것.** 조화 성분이
거의 없는 구간에서 그 둘은 값 자체가 불안정하다. 비조화를 먼저 잡고 나서 봐야
§8 에서 기각한 가설들을 다시 밟지 않는다.

첫 실험: 마찰 구간에서 합성의 비조화가 **어디서** 오는지 가른다 — 마찰 소스인가,
기식인가, 지터·시머인가, 시변 필터의 계수 변조인가. `scripts/probe_texture.py` 의
변조 스펙트럼과 `engine/waveform.decompose` 의 잔차를 대역별로 보면 좁혀진다.

### 9.1 코퍼스를 통째로 파라미터화한다

`scripts/parametrize_corpus.py` 가 준비돼 있다. 45 분 코퍼스를 200 ms 구간으로 쪼개면
수천 개이고, 구간당 2~4 분이면 며칠 분량이다. 먼저 **예산과 품질의 맞바꿈을 재라** —
`--budget` 을 40/30/100 부터 200/150/800 까지 훑어 포락·잡음비가 어디서 포화하는지.
`--patience` 가 이미 붙어 있으므로 수렴한 구간은 알아서 일찍 끝난다.

`--jobs` 는 코어 수의 절반쯤으로. 작업 단위가 파일이라 부하가 고르지 않다.

### 9.1b 학습 데이터의 **물리적 타당성**을 먼저 검사하라

파이프라인이 낸 첫 트랙(모음 260 ms, 예산 40/30/100)에서:

    p_sub     중앙 15.7 cmH2O  (범위 12.4 ~ 17.2)
    adduction 중앙 0.865       (상한 0.85 근처에 붙어 있다)

**보통 세기의 모음인데 p_sub 가 15.7 이면 큰 소리로 외치는 값이다.** `fit.py` 의
`GLOBAL_PARAMS` 주석이 정확히 이 현상을 경고한다 — 전역 이득과 `tract_gain` 이 서로를
상쇄하며 떠돌면 그 사이에서 `p_sub` 가 끌려간다(실측 17.6).

예산이 작아서(40/30/100) 수렴이 덜 된 것일 수도 있으므로 **먼저 예산을 올려 다시
보라.** 그래도 남으면 `p_sub` 의 사전(PRIOR_W 3.0)이 모자란 것이고, 그 상태의 트랙을
학습에 먹이면 신경망이 "모든 모음은 외치는 소리" 를 배운다.

검사 방법: `index.jsonl` 과 npz 를 훑어 파라미터별 분포를 뽑고, 생리적 범위
(p_sub 5~10 대화, 10~15 큰 소리)와 대조한다. `ok` 플래그는 스펙트럼 일치만 보므로
이걸 못 잡는다 — **판정에 물리 범위를 넣을지 정해야 한다.**

### 9.2 `spectrum_match` 의 남은 격차를 좁힌다

치찰음 구간에서 대역 MAE 는 0.23 dB 인데 시간평균 스펙트럼 일치는 61.7 % 다. 대역
평균은 맞고 **세부 구조가 안 맞는다**는 뜻이다. 어느 주파수에서 벌어지는지 먼저 재라 —
`turbulence.average_psd` 로 목표와 합성의 dB 곡선을 그대로 빼 보면 바로 보인다.

후보: 앞공동 극의 대역폭(`front_bw_slope`), 뒤공동 노치의 깊이, 12 kHz 위의 롤오프.

### 9.3 `analyze.py` 의 마찰 판정을 고친다

무성 + 고역/저역비 > 0 dB 로는 **치찰음과 호흡·기식이 안 갈린다** (§8.4). 이 마스크는
`tract_gain` 고정과 `fric_gain` 보정에 쓰이므로 초기값에 직접 영향을 준다.

문턱을 감으로 바꾸지 말 것. 코퍼스에서 치찰음/호흡/비음 머머의 (고역저역비, 무게중심,
치찰도) 분포를 먼저 재고, 세 무리가 갈리는 면을 찾아라. `engine/segment.py` 가 이미
그 계산을 다 하고 있으므로 분포를 뽑는 데 몇 분이면 된다.

### 9.4 가속도 벌점(`VEL_W`)을 켤지 정한다

§4 가 남긴 숙제다. 기본값이 아직 0 이다. **위상 항이 바뀐 지금 다시 재야 한다** —
§4 의 표는 예전 위상 항으로 얻은 것이고, 그 항이 마찰 구간에서 소리를 끄고 있었다.
`scripts/bench_corpus.py` 로 VEL_W 0 / 0.001 / 0.003 을 훑어라.

### 10.2 다시 밟지 말 것

* **`obstacle` 을 0 으로 두지 말 것.** `fit._to_raw` 가 로짓이라 0 은 기울기가
  1e-4 로 죽는 구간이고, `PRIOR_W` 10 이 거기 묶는다. `lat_mix` 와 같은 함정이다.
  **"0-1" 종 파라미터를 새로 쓸 때마다 초기값이 경계에 붙어 있는지 확인하라.**
* **다이폴을 제트 *속도*로 재려 하지 말 것.** 무성 마찰음은 성문이 크게 벌어져
  있어 협착부 속도가 베르누이 상한에 붙는다. v1 과 v2 가 독립으로 같은 결론에
  도달했고, v2 에서는 vel_exp 0 과 1 이 **바이트 단위로 같은 출력**을 냈다.
* **§12.3 의 "기각된 가설 여섯" 을 그대로 믿지 말 것.** 그 여섯은 전부 **파일
  전체**를 한 덩어리로 재는 자로 기각됐다. §13 이 보였듯 유성 구간과 마찰 구간은
  부호가 반대다(0.73 배 대 5.50 배). 다시 볼 가치가 있는 것이 있으면
  `turbulence.env_modulation_index` 로 **프레임을 갈라서** 재라.
* **적합 결과를 다시 렌더해서 A/B 하지 말 것 — 꼭 해야 하면 `copyfit` 과 같은
  `EngineConfig`(시드 0, `residual=False`)를 쓰고 시드를 바꾼 대조군을 같이
  놓아라.** 이 함정에 한 번 빠져 결론 둘을 잘못 냈다(§17). 난류가 든 대역에서는
  **실현 하나가 트랙 조작보다 크게 움직인다** — 시드만 바꿔도 마찰 프레임의
  60~150 Hz 변조가 2.33 → 4.57 배로 뛰고 0~80 Hz 가 12.8 dB 움직인다(통로는
  전부 지터·시머다). 가장 안전한 길은 저장된 `_fit.wav` 를 그대로 재는 것이고,
  `scripts/report_sizzle.py` 가 그것만 한다.
* **성대 소스를 더 스무딩하지 말 것.** 이론은 맞지만 (§15.1) 기제는 LF 의 귀환
  위상 Ta 하나이고 이미 모형에 있으며, 적합기가 이미 코너를 2190 → 481 Hz 로
  내려 쓰고 있다. 지금 우리 소스는 목표보다 고조파가 **모자라는** 쪽이다.

## 12. 0.3.14 — **자를 세 번 고쳤고, 세 번 다 결론이 뒤집혔다**

이번 세션의 교훈은 한 줄이다. **판정이 이상하면 대상보다 자를 먼저 의심하라.**
세 번 모두 "모형이 나쁘다" 로 보였던 것이 자의 결함이었다.

### 12.1 s040 의 회귀는 벌점 탓이 아니었다 (§27)

`out/v13/s040` 이 포락 91.28 → 84.29 % 로 무너져서 새로 켠 두 벌점 중 어느 쪽인지
가르려 했는데, **둘 다 아니었다.** 위상 단계(3 단계)는 크기를 잠시 놓고 위상을
맞추므로 **항상 한 번 꺾였다가 200 회에 걸쳐 회복한다**:

    room2/s040  3 단계 [0] 92.34 → [50] 84.67 → [100] 91.62 → [199] **93.05**

v13 은 그 42 회 중 27 회가 비유한 기울기로 건너뛰어졌는데, 가드가 **걸음만 건너뛰고
정체 계수는 그대로 올려서** 골짜기 한복판(84 %)에서 멈췄다. 고쳤다.

> **위상 단계의 중간 값을 보고 판단하지 말 것.** 200 회를 다 돌기 전에는 항상 나쁘다.

비유한 기울기 자체는 아직 원인 미상이다. `FORMANT_ML_DEBUG_NONFINITE=1` 이 어느
파라미터·격자점인지 찍는다. 짧은 구간(0.18~0.55 s)에서는 4 벌 모두 0 회였고 전체
파일에서만 났으므로, 무음이 낀 구간을 의심하라.

### 12.2 저역 초과의 정체는 제어열 잔물결이다 — 이번엔 인과까지 (§26)

`f0_target` 만 빼고 제어열을 이동평균으로 뭉개고 다시 렌더하면 F0 아래 초과가
**단조로 사라지는데 하모닉은 ±1.1 dB 로 꿈쩍도 안 한다** (47 Hz: +26.7 → +4.9 dB).
잡음 경로가 아니라 성문 소스 `du` 안에 있다 — 기식·마찰은 25 dB 아래다.

**그리고 이것이 §23 의 `RIPPLE_W` A/B 가 "판정 불가" 였던 이유다.** F0 아래 대역은
유성 프레임 총에너지의 1 % 도 안 되므로 **멜 포락 손실에는 원리적으로 안 보인다.**
귀에는 들린다. 앞으로 잔물결은 손실이 아니라 `acceptance.subf0_excess_db` 로 판정한다.

### 12.3 §24 의 받개가 조음을 얼렸다 (§29)

`pseudo_huber(rate/knee)` 는 무릎 **아래**에서도 이차로 벌한다. `a_c` 속도 95 분위가
0.449 → **0.015** neper/ms 가 됐다 — 가장 빠른 실제 제스처(0.172)의 11 배 **아래**다.
그 결과 고치려던 것이 **오히려 나빠졌다**: 유성 구간 마찰 켜짐 1.30 → 18.86 %.
협착이 못 닫히니 레이놀즈 게이트를 계속 넘는 것이다.
`softplus` 로 초과분만 취해 한계 아래를 정확히 공짜로 만들었다.

### 12.4 합격 판정이 무음을 채점하고 있었다 (§30)

마스크가 적합 트랙의 `p_sub > 2` 였는데, 적합기는 무음에서 `p_sub` 를 아무 데나 둔다
(손실이 0 이라 기울기가 없다). s040 의 목표 무음 21 프레임 **전부**가 "소리남" 으로
셈해졌고, 그 −80 dB 짜리 대역 dB 의 잔떨림이 세로 얼룩 지표를 통째로 오염시켰다.

목표 레벨(정점 −45 dB)로 바꾸니 `out/room2/s040` 이:

    세로 얼룩 p95 1.532 → **1.150**,  무게중심 r 0.927 → **0.988**,
    기울기 r 0.765 → **0.924**,  기울기 오차 1.788 → **1.407**

**"s040 은 네 조건을 못 통과한다" 의 절반이 자의 결함이었다.**

### 12.5 적합의 `jitter` 는 지터가 아니다 (§28)

`f0_target` 이 펄스에서 온 비평활 트랙이라 화자의 실제 지터를 이미 담고 있다.
`jitter`=0 에서 실현 지터가 1.88 % 로 이미 목표(1.45 %)보다 크고, `jitter` 를 올리면
오히려 내려간다. 실제로는 대역 초과(특히 150 Hz 를 2.6 dB)를 깎는 손잡이로 쓰인다.

**학습 데이터로 나가는 물리량이 오염된다.** 뿌리인 잔물결(§26)을 잡으면 `jitter` 가
대신 메울 것도 없어진다 — 그래서 잔물결부터다.

합격 조건 4 도 "지터가 낮다" 에서 **"실현 지터가 목표와 같다"** 로 바꿨다.

### 12.6 확정된 이득

`glottis.TILT_MAX_HZ = 5000` (성대 스무딩) 은 **모든 축에서 이긴다** — 같은 구간
재적합에서 포락 +1.6, 세로 얼룩 −0.09, F0 아래 −5.2 dB. §25 의 재렌더 A/B 는
"대가 0.04 dB" 라고 했는데 다시 적합하면 오히려 이득이다.
**재렌더로 잰 대가는 재적합의 대가가 아니다.**
