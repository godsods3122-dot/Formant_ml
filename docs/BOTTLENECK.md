# 병목 분석 — 복사합성 적합기가 어디서 막혀 있는가 (2026-09-13)

앞선 인수인계는 `docs/HANDOFF.md` (2026-09-08) 다. 그 문서는 **막다른 길의 목록**이고
이 문서는 **남은 오차가 어디 있는지의 측정**이다. 둘 다 읽어야 한다.

이 문서는 **다음 작업자(사람이든 모형이든)** 가 이 프로젝트를 이어받기 위한 것이다. 결론부터
쓰고, 그 결론을 만든 측정과 그 측정을 재현하는 명령을 전부 적는다. 추측과 측정을 섞지 않는다.

## 0. 한 문단 요약

목표는 **녹음과 합성을 사람이 구분하지 못하는 수준**이다. 현재 포락 일치율은 s101 87.0 %,
s040 89.7 % 이고 일주일 넘게 88~90 에서 멈춰 있다. 그 동안 손잡이(보조 극·영점·이벤트 층·
붙잡기 등)를 계속 더했는데, 이번에 오차를 분해해 보니 **그 손잡이들이 다루는 영역이 남은
오차의 0.6 % 이하**였다. 남은 오차의 85~94 % 는 **유성 구간 0~3 kHz** 에 있고, 그 정체는
**개별 배음의 크기가 프레임마다 3 dB 씩 틀리는 것**이다. 그리고 그 배경에 구조적 원인이 하나
있다 — **성도 극의 Q 가 관측 단계에서부터 3~12 로, 실제 성도(15~40)보다 3~8 배 과감쇠다.**

### **이번 세션의 어떤 판도 `M1` 을 이기지 못했다.**

솔직히 적는다. `M1` 은 이 세션이 시작되기 전의 판이고, 그 뒤에 넣은 것(붙잡기 램프 비대칭,
보조 영점 3, 고역 영점 3, 고역 마루 3, 물결 손실, 강화 이벤트, `PHASE_PATIENCE` 해제)을 다
합쳐도 **s101 88.70 → 86.79** 다.

원인은 §3 의 ROI 표와 일관된다. 더한 기구들이 다루는 영역(6 kHz 위)은 **완벽히 고쳐도 +0.6 점**
인데, 그것을 위해 적합 열이 33 → 42 개로 늘었다. §40 에 기록된 **열 희석**(열이 32 → 40 이 되자
2.4 단계가 회복을 못 했다)이 그대로 재현된 것으로 보인다. 즉 **더한 값보다 희석 비용이 컸다.**

`PHASE_PATIENCE` 회귀는 진짜지만 크기는 작다. `M16` 이 위상 400 회를 다 돌아 2.4 단계 끝
86.15 → 86.79 로 **+0.64** 를 벌었다 (`M1` 에서는 +2.75 였다). 즉 `M13`·`M14` 가 `M1` 보다
낮았던 것의 대부분은 조기 종료가 아니라 **열 희석**이다.

## 2. **이 지표에는 천장이 있다** — 96 % 는 s101 에서 불가능하다

마찰·기식은 난수라 어떤 모형도 목표의 그 실현을 맞출 수 없다. 목표 녹음만으로 상한을 쟀다:
목표의 STFT 크기를 **한 칸도 빠짐없이** 그대로 두고 **잡음 우세 칸의 위상만** 새로 뽑은 대리
신호를 만들어 점수를 매긴다. 이보다 관대한 모형은 있을 수 없다.

| | 천장 | 현재 | 여유 |
|---|---|---|---|
| **s101** | **92.48 %** | 87.03 | 5.45 |
| **s040** | **96.73 %** | 89.73 | 7.00 |

대조군(위상을 **하나도** 안 바꾼 왕복): **100.00 %**. 측정 자체의 손실은 0 이다.

> 재현: `python "$TMP/ceiling.py" out/M/M14/s101 out/M/M1/s040`
> (스크립트는 §8 에 전문이 있다)

**함의.** 절대 96 % 는 s101 에서 물리적으로 불가능하다. 목표는 **천장 대비**로 바꿔야 한다.
지금은 s101 이 천장의 94.1 %, s040 이 92.8 % 다. 그리고 이 천장은 **무성·마찰 구간의 난수**
때문이지 유성 구간 때문이 아니다 — 유성 구간만 보면 대조군의 배음 오차가 **0.00 dB** 라 천장이
없다 (§4). 그러므로 옳은 설계 목표는 **"유성은 거의 완벽히, 무성은 통계적으로"** 다.

## 4. 남은 오차의 정체 — 배음 크기가 3 dB 틀린다

2048 창(23 Hz 분해능)에서 유성 프레임의 배음 봉우리를 차수별로 비교했다.

| k | 1 | 2 | 3 | 4 | 6 | 10 | 16 | 20 |
|---|---|---|---|---|---|---|---|---|
| **부호 있는** Δ진폭 [dB] | −0.09 | +0.41 | −0.47 | +0.80 | +0.19 | −0.86 | −0.71 | −0.14 |
| **절대** \|Δ진폭\| [dB] | 0.26 | 1.31 | 2.42 | 2.97 | 3.01 | 3.33 | 4.06 | 3.35 |
| \|Δ주파수\| [센트] | 11 | 21 | 21 | 18 | 27 | 22 | 17 | 19 |

**아닌 것들을 하나씩 배제했다.**

* **정적 기울기·롤오프 오차가 아니다** — 부호 있는 오차가 전 차수에서 0 근처다.
* **F0·지터가 아니다** — 주파수 오차가 11~36 센트뿐이다.
* **포먼트 자리가 아니다** — \|Δ진폭\| 과 국소 스펙트럼 기울기 \|dH/df\| 의 **상관이 +0.016**.
  가장 평탄한 20 % 구간에서도 오차가 2.73 dB 다.
* **실현 잡음이 아니다** — 대조군(잡음 위상만 새로)의 배음 오차가 **0.00 dB**(95 % 1.34).
  참고로 전 구간 위상을 새로 뽑으면 6.21 dB 다. 즉 우리는 "맞음" 과 "완전히 틀림" 의 **중간**이다.

> 재현: `python "$TMP/harm.py" out/M/M14/s101` / `slope.py` / `harmctl.py`

**창이 길수록 점수가 나빠지는 것**(정밀 `256:83.1 512:84.9 1024:82.3 2048:78.6 4096:76.3`)은
이것의 그림자다 — 짧은 창은 이웃 배음을 뭉개서 ±3 dB 를 상쇄시켜 준다. **창을 줄이는 것은 오차를
숨기는 것이지 고치는 것이 아니다.**

## 5. 구조적 원인 후보 — **극이 과감쇠다** (가장 중요)

적합된 궤적을 물리와 맞대어 봤다.

| | 관측(분석기) | 적합 결과 | 생리 범위 |
|---|---|---|---|
| bw1 | 141 (59) | 223 (181) | **40~90 Hz** |
| bw2 | 352 (256) | 270 (196) | **60~120 Hz** |
| bw3 | 444 (394) | 457 (668) | **80~160 Hz** |
| bw4 | 382 (431) | 361 (655) | **100~200 Hz** |

(괄호는 s040. 유성·비마찰 프레임 중앙값.)

**Q = f/bw 로 보면 더 분명하다.**

| | Q1 | Q2 | Q3 | Q4 |
|---|---|---|---|---|
| s101 관측 → 적합 | 3.3 → 2.1 | 5.7 → 7.3 | 8.0 → 7.8 | 12.2 → 13.8 |
| s040 관측 → 적합 | 9.7 → 3.0 | 7.4 → 10.0 | 9.1 → 5.3 | 10.5 → 7.6 |
| **실제 성도** | **15~40** | 15~40 | 15~40 | 15~40 |

**과감쇠는 적합기가 만든 것이 아니라 관측 단계에서 이미 있다** (적합/관측 비 0.77~1.70).

### 왜 그럴 수 있는가

이 화자의 **F0 중앙값이 295 Hz** 다 (`wavs/` 20 개 실측, 5~95 % 231~405 Hz). 배음 빗살이
전달함수를 **270~300 Hz 마다 한 번씩만** 표본한다. 대역폭 60 Hz 짜리 극이 두 배음 사이에 있으면
**원리적으로 보이지 않는다.** 매끈한 포락(LPC·켑스트럼)으로 대역폭을 추정하면 고 F0 화자에서
체계적으로 과대평가된다 — 알려진 어려운 문제다.

### 이것이 설명하는 것들 (전부 사용자가 청취로 지적한 것)

* *"원본은 공진이 매우 잘 느껴져서 자극적으로 딱 청취가 되는데, 우리 건 퍼진 소리 같고 산란이
  많이 일어난 듯한 목소리"* — Q 5~10 은 공진이 아니라 넓은 어깨다.
* 감사의 **F2·F3 돌출 얕은 창 36 % / 44 %** — 봉우리가 얕은 직접적 결과.
* **골이 얕다** — 같은 원인의 반대쪽. 그래서 영점을 넣어도 절반만 고쳐진다.
* **§4 의 배음 3 dB** — 전달함수가 너무 매끈하면 배음 하나하나의 값을 맞출 수단이 없다.

### 그런데 대역폭을 좁히면 점수가 **떨어진다**

기록이 있다 (`tests/engine/test_analyze_fit.py`, §35.4): `BW_LAW_W` 0 → 0.5 로 포락 92.44 →
85.79 %, 2.0 → 89.63 %. 당시 결론은 *"대역폭 과대의 원인이 극 부족이 아니므로 법칙으로 좁히면
맞출 수단만 뺏는다"* 였다.

**이 모순이 문제의 핵심이다.** 손실이 **매끈한 포락**(5.3 ms 창, 187 Hz 분해능의 멜 띠)을
비교하는 한, 좁은 극은 손해다 — 손실은 뾰족함을 요구하지 않으면서 평균만 맞기를 원한다.
좁은 극이 이득이 되려면 **손실이 배음 하나하나를 봐야 한다.**

즉 **관측·손실·모형 셋이 같은 오류를 공유한다**: 셋 다 배음 분해능 아래에서 일한다.

## 7. 다음 작업자에게 주는 문제

> **유성 구간 0~3 kHz 에서 개별 배음의 크기 오차를 3 dB → 1 dB 로 줄여라.**
> 부수 조건: 성도 극의 Q 가 생리 범위(15~40)에 들어야 하고, 그러면서 점수가 떨어지지 않아야 한다.

이 둘은 지금 서로 모순이다 (§5). 모순을 푸는 것이 과제다. 유력한 방향은 셋이고, 셋 다 검증이
필요하다.

1. **손실을 배음 분해능으로 올린다.** 유성 프레임에서 k·F0 자리의 크기를 직접 비교하는 항.
   지금 포락 손실은 5.3 ms 창의 멜 띠인데, 12 kHz 멜 띠 폭이 516 Hz 이고 F0 가 295 Hz 다.
2. **관측(분석기)의 대역폭 추정을 고친다.** 매끈한 포락이 아니라 **배음 표본에 소스-필터
   모형을 맞추는** 방식으로. 고 F0 화자의 대역폭 추정 문헌을 찾아볼 것.
3. **극의 개수·배치를 물리로 다시 세운다.** 16 kHz 아래 있어야 할 극 수는 2L·16000/c 로
   L=12~13 cm 면 **11~12 개**다. 지금 엔진은 F1~F8 + 여분 사다리 + 비강 16 개 + 보조 7 개 +
   영점들이다 — **개수 자체가 물리보다 많고**, 그래서 서로 녹아 평평해질 수 있다. 사용자의
   의문(*"극을 너희들이 어떻게 잡았는지, 그게 물리랑 맞는지조차 잘 모르겠고"*)이 여기다.

**하지 말 것.** 6 kHz 위를 더 파는 것(전부 고쳐도 +0.15~0.60). 손잡이를 더 다는 것 — 손잡이가
아니라 손실이 문제다. 창 길이를 바꿔 점수를 올리는 것 — 오차를 숨기는 것이다.

## 8. 일하는 규칙 (비싸게 배운 것)

* **손잡이를 더하면 기울기를 확인한다.** `∂손실/∂값` 을 임펄스 응답으로 찍어 본다. 0 이면
  그 판은 통째로 낭비다 (`M11`·`M12` 가 그랬다).
* **쓰지 않는 열은 얼린다.** 엔진이 안 쓰는 파라미터가 적합 대상에 남으면 열 희석만 일어난다.
* **목표가 도달 가능한지 먼저 잰다.** 천장 측정(§2)은 3 분이면 된다. 이것을 일주일 늦게 했다.
* **시뮬 비용을 줄이는 법**: `--init <이전 판> --global-iters 0 --stage-iters 0 --phase-iters 0`
  으로 **제어열을 그대로 두고 렌더만** 다시 한다 (한 판 3 분). 음원 쪽 A/B 는 전부 이걸로 된다.
* **중앙값으로 판정하지 않는다.** 최악값과 구간별로 본다.
* **한 파일로 상수를 정하지 않는다.** `PHASE_PATIENCE` 가 그렇게 망가졌다.
* 최대 3 판 동시, 여유 메모리 14 GB 이상.

## 10. 배음 크기 목적함수의 첫 구현

`copyfit --harmonic 1` (기본값)은 유성·비마찰 0~3 kHz의 배음별 상대 크기를 직접 맞춘다.
기존 2048 표본 창을 유지하되, 목표 펄스의 주기 위상(펄스가 없으면 F0의 누적 위상)으로 만든
사인·코사인 기저에 가중
최소제곱을 적용한다. FFT 최대 빈의 크기를 쓰지 않으므로 빈 사이 위치에 따른 진폭 편향을
피한다. 투영 행렬은 목표에서 한 번만 만들며, 합성 엔진에는 새 연산이나 제어열을 넣지 않는다.
`--init`으로 적합된 F0가 들어와도 목표 펄스가 우선하며, 펄스 범위 밖은 관측 창에서 제외한다.

창 전체가 유성·비마찰인 곳만 사용하고, 목표 창 정점 대비 -60 dB 아래의 창, 창의 최강 배음
대비 -40 dB 아래 또는 잔차로 추정한 계수 잡음보다 10 dB 이상 크지 않은 배음은 제외한다.
가중은 목표에서 고정되며 유효 배음은 창 안에서 동등하게 취급한다. 창마다 정규화하므로 낮은
F0가 단지 배음 개수가 많다는 이유로 목적함수를 지배하지 않는다. 배음 사이 골의 잡음은
기존 HNR·위상·스펙트럼 항이 계속 담당한다.

배음 관측이 있는 구간에서는 초기 중심이 0~3 kHz에 있는 포먼트의 BW를 평활 분석 초기값에
묶는 사전만 제거한다. 대역 밖 포먼트와 관측 창이 없는 구간의 사전은 유지한다.
포먼트 위치 사전, 시간 제약, 물리 범위는 유지한다. 이것은 실제 BW가 관측됐다는 뜻이 아니며,
Q를 일률적으로 15~40에 가두지도 않는다. 새 BW 추정기나 성도 구조 변경은 포함하지 않는다.
`--harmonic 0`은 새 손실을 끄고 이전 BW 사전을 유지하는 대조군이다. **적합 열 증감은 0**이다.

보고서의 `harmonic`에는 창별 평균을 다시 평균한 `mae_db`, 배음 관측 전체의 `p95_db`·`max_db`,
차수별 값, 유효 관측·창 개수를 저장한다. 유효 창이 없으면 오차는 0이 아니라 `null`이다.
기존 포락 계산과 평가 창은 바꾸지 않았다. **96% 포락이나 1 dB 배음 오차 달성이 확인된
변경은 아니다.** 기존 `harm.py`와는 진폭 추정법·지지 구간이 다르므로 숫자를 직접 이어 붙이지 않는다.

## 11. 공통 상수 분리와 기존 배선 수정

이번 단계의 목표는 91%대 포락으로 가는 기반 정리다. 비선형 소스-필터 피드백, 새 성대 모델,
고역 사다리 교체, 새 BW 관측기는 아직 넣지 않았다. 아래 수정 자체가 포락 상승이나 청감 개선을
입증한 것은 아니다.

### 상수의 범위

`engine/calibration.py`가 이름·소유 모듈·공유 범위·기존 저장 필드의 단일 목록이다.
`SpeakerProfile`의 해부/제스처 초기값과, 적합된 경험적 보정값은 별도 파일로 유지한다.

| 범위 | 내용 | 공유 정책 |
|---|---|---|
| `speaker` | 고차/앞공동 BW 보정, 고역 극·이상와 보정, 마찰 절벽 비율, 개방기 감쇠 계수 | 제공된 항목만 여러 발화에서 재사용·잠금 |
| `recording` | 합산 출력의 HF EQ와 활성 여부, 방/마이크 IR | 동일 녹음 환경에서 별도로 재사용 |
| `utterance` | MVF, 성문 위상 분산, 음원 EQ, 레벨 정규화, 펄스 위상 오프셋 | 화자 평균이나 화자 잠금에 넣지 않음 |

`gain_db`는 발화별 레벨 정규화이지 장비 이득의 직접 측정이 아니다. 출력 EQ 역시 녹음 경로의
경험적 보정이며, 실제 마이크 응답으로 식별됐다는 뜻은 아니다. 공통 보정값을 잠가도
F1~F4·BW·폐압·내전 등 발화 제어를 새로 고정하지 않는다. 기존 선택 기능을 자동으로 켜지도
않는다. 단, 저장된 녹음 EQ의 활성 상태는 엔진 인스턴스별로 복원한다.

`copyfit`은 `*_track.npz`의 `acoustic_constants`와 별도 `*_constants.json`에 세 범위를 저장한다.
기존 `engine_params`·`hf_params`·`asp_params`도 계속 쓴다. 예전 NPZ와 평면 화자 JSON도 읽되,
MVF·음원 EQ 등을 화자 상수로 오인하지 않는다. 잘못된 모양이나 서로 다른 모델을 조용히 잘라
끼우지 않고 오류로 알린다. 부분 화자 파일을 읽었다고 나머지 전역값까지 전부 잠그지 않는다.

```powershell
# 이미 적합된 두 발화에서 화자 공통 초기값을 만든다.
python scripts\speaker_profile.py out\run\s040 out\run\s101 -o profiles\yang_shared.json
python scripts\copyfit.py data\voices\yang_00000101.wav --profile profiles\yang_female.json --speaker-lock profiles\yang_shared.json --out out\next\s101

# 녹음 경로는 화자와 별도 선택한다. 입력에 실제로 보정된 EQ/IR이 있어야 의미가 있다.
python scripts\speaker_profile.py out\run\s040 --scope recording -o profiles\room_a.json
python scripts\copyfit.py data\voices\yang_00000101.wav --profile profiles\yang_female.json --speaker-lock profiles\yang_shared.json --recording-lock profiles\room_a.json --out out\next_room\s101
```

여러 발화의 중앙값은 공통값의 초기 추정이지 다발화 공동 최적화가 아니다. 서로 다른 차원의 극
배열이나 누락된 항목을 섞지 않는다. 서로 다른 IR도 평균하지 않는다. 하나의 녹음 경로 보정을
선택해야 한다. `--bands`는 기존의 선택 기능이며 기본으로 켜거나 Q 구역을 추가하지 않는다.
공통 구역을 명시한 경우에는 같은 구역으로 초기 raw 좌표를 만들어, 구역 안의 초기 포먼트를
불필요하게 이동시키지 않는다.

`parametrize_corpus.py`도 `--speaker-lock`·`--recording-lock`을 받고 각 구간 NPZ에 같은 범위 정보를
저장한다. 새 녹음 환경에 기존 방 IR을 무조건 적용하지 말 것. 선택한 고역/잡음 구조 등 나머지
렌더 옵션은 별도로 동일하게 지정해야 한다.

### 상태와 이벤트

`NOISE_V2` 잡음 사다리의 상태를 `noise_x*`로 분리했다. 비강 사다리의 `nx*`와 더 이상 충돌하지
않는다. 연구개가 닫힌 청크에서도 이미 존재하는 비강 상태는 무입력 응답으로 감쇠한다.
상태도 없고 정확히 닫혔으며 열림 기울기도 필요 없는 경우에만 계산을 건너뛴다.

이벤트 검출은 F1~F3의 공통 빠른 프레임 목록에 의존하지 않는다. `EVENT_PARAMS`에 속하고 실제
적합 대상인 각 제어에서 전이를 찾는다. `front_len`만 움직여도 그 위치에 이벤트가 생기며,
0에서 시작하는 `obstacle`도 처리한다. 반대 방향의 전이는 합치지 않는다.
계수는 움직인 제어/이벤트 쌍에만 하나씩 두고, 진폭 제한도 해당 제어의 관측 raw 좌표 변화량으로
계산한다. 기존 액션/이벤트 벌점은 이 희소 대응에 맞춰 적용하며, 기본 `EVENT_W=0`은 유지한다.
이는 전체 조음의 생리 동역학을 완성한 변경은 아니다.

### 자유도와 재렌더

**새 프레임 제어열은 0개**다. 이전의 경계 하나당 최대 8개 이벤트 계수 대신, 움직인 제어 하나의
전이라면 1개만 할당한다. 새로 찾는 전이가 많으면 총계는 늘 수 있으므로 보고서에 실제
`event_coefficients`를 기록한다. `constant_budget`은 범위별 적합/잠금 상수의 이름과 스칼라 수,
`frame_controls`는 실제 적합 제어열 수다.

`HF_FIXED`가 꺼졌는데도 최적화 목록에 들어가던 고역 위치·BW·이상와 값도 제외했다.
기본 K=8, 여분 6개에서는 비활성 전역 스칼라 22개이며, 프레임 열을 22개 줄였다는 뜻은 아니다.
공통 파일에 비활성 가지 값이 있으면 저장값은 유지하고 CLI가 비활성임을 표시한다.

`--init`은 빠졌던 음원 EQ·출력 EQ와 이득, 저장된 방 IR·펄스 오프셋도 복원한다. 저장 이득이 있으면
초기 레벨 보정으로 제어를 다시 바꾸지 않는다. 제어 프레임 간격과 이름도 확인한다.
다음 명령은 이제 학습률 탐침, 펄스 위상 탐색, 격자 교체까지 건너뛰고 현재 해만 평가한다.
기존에는 반복 수가 0이어도 전역 학습률 탐침과 펄스 위상 탐색이 실행될 수 있었다.

```powershell
python scripts\copyfit.py data\voices\yang_00000101.wav --profile profiles\yang_female.json --init out\run\s101 --global-iters 0 --stage-iters 0 --phase-iters 0 --out out\rerender\s101
```

별도의 `--hf-stage`를 지정했다면 그것은 추가 적합 예산이다. 제어를 완전히 유지할 때는 켜지 않는다.
고역 단계만 명시한 경우에도 펄스 위상 탐색이나 제어 격자 교체는 실행하지 않는다.
예전 `q_band`는 메타데이터로 보존하지만 화자 잠금만으로 Q 제약을 활성화하지 않는다.

## 12. Optional impedance-loaded source

`--glottal-source loaded --load-coupling 0.7` selects a prescribed-LF flow
source with nonlinear resistance/inertance and stateful passive input-load
feedback. The default remains LF; zero coupling is an exact legacy bypass.
There are no new fitted controls/scalars. See [IMPEDANCE_SOURCE.md](IMPEDANCE_SOURCE.md)
for units, the implicit solve/adjoint, saved-mode A/B semantics, fixed
reference-flow assumptions, differentiation effects, and limitations.
This is not a self-oscillating fold model or evidence of improved envelope/
harmonic accuracy. Existing evaluation windows and objectives are unchanged.
