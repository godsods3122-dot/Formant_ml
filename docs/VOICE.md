# 목소리를 만들고 조종하기

이 문서는 세 가지를 다룬다.

1. **조종** — 원하는 소리를 스크립트로 지정하는 법 (§1~§3)
2. **추출** — 실제 녹음에서 그 사람의 목소리를 숫자로 뽑아내는 법 (§4)
3. **한계** — 각 추정이 어디까지 믿을 만한지, 측정치와 함께 (§5)

---

## 1. 설계 원칙: 특별한 소리는 없다

웃음도 치찰음도 성대 프라이도 별도의 코드 경로가 아니다. 전부 **같은 물리
손잡이의 다른 조합**이다. 예를 들어 웃음 '하하하' 는 다섯 줄로 요약된다.

| 물리적 사실 | 손잡이 |
|---|---|
| 호기 압력이 5~7 Hz 로 끊어진다 | `harmonic_amp` / `noise_bands` 의 주기적 포락선 |
| 펄스마다 F0 가 튀어오른다 | `f0` × 펄스 포락선 |
| 성문 마찰(/ㅎ/)이 함께 난다 | `noise_entry` = 0 (성문 주입) + 넓은 대역 |
| 펄스가 짧아 성문파가 눌린다 | `rd` 를 pressed 쪽으로 |
| 뒤로 갈수록 공기가 빠진다 | `rd`, `noise_am` 을 breathy 쪽으로 램프 |

`gestures.py::laugh` 가 정확히 이 다섯 줄이다. `rate_hz`, `voiced`,
`breathiness`, `pitch_lift` 만 바꾸면 껄껄/킥킥/헛웃음/소리없는 웃음이 된다.
그래서 "반쯤 웃으면서 말하기" 같은 것도 두 상태를 섞으면 그냥 나온다.

## 2. 스크립트

```yaml
name: 예제
voice: profiles/me.json        # 없으면 기본 프로파일
seed: 7
smooth_frames: 3               # 세그먼트 경계 평활(프레임 수)

timeline:
  - {type: syllable, onset: s, vowel: a, dur: 0.5, f0: [150, 128]}
  - {type: laugh, dur: 1.2, rate_hz: 5.5, voiced: 0.85, tilt: 3.0}
  - {type: breath, dur: 0.35, inhale: true}

params:                        # 발화 전체에 걸리는 값
  jitter: 0.005
```

세그먼트 타입: `vowel` `glide` `fricative` `syllable` `silence`
`laugh` `breath` `sigh` `creak` `whisper` `sob` `throat_clear`

값 형식은 **모든 파라미터에 공통**이다.

```yaml
rd: 1.2                                  # 상수
rd: [0.5, 2.2]                           # 시작 -> 끝 선형
rd: [[0, 0.5], [0.7, 0.5], [1, 2.2]]     # 브레이크포인트 (위치 0~1)
```

## 3. 파라미터

### 성문 소스
| 이름 | 뜻 | 범위 |
|---|---|---|
| `f0` | 기본주파수 | 55~880 Hz |
| `harmonic_amp` | 유성 성분 세기 (0 = 무성) | 0~ |
| `rd` | 성문파 형상 = 개방지수 | 0.3 pressed ~ 2.7 breathy |
| `tilt` | **소스 스펙트럼 기울기** | −12~+12 dB/oct (1 kHz 기준) |
| `jitter` | 주기 요동 비율 | 0~0.03 |
| `shimmer` | 진폭 요동 비율 | 0~0.3 |

`tilt` 가 고역 담당이다. LF 의 `Rd` 만으로는 고역 감쇠 *모양*이 고정이라
6~12 kHz 를 원하는 만큼 살릴 수 없다. `tilt` 는 로그주파수에 대한 직선이라
고역만 정확히 그만큼 올린다 (측정: ±8 dB/oct → 5 kHz 위 에너지 16 dB 변화).

### 성도
| 이름 | 뜻 |
|---|---|
| `f1` … `f12` | 각 포먼트 주파수 [Hz] |
| `bw1` … `bw12` | 각 포먼트 대역폭 [Hz] |
| `formant_freq` / `formant_bw` / `formant_gain` | 전체를 리스트로 |
| `area` | 도파관 모드의 단면적 함수 [cm²] |

포먼트는 12 개다 — 나이퀴스트(12 kHz)까지 대략 1 kHz 당 1 개. 6 개로 덮으면
최상단 극 위에서 캐스케이드가 극당 −12 dB/oct 로 겹쳐 떨어져 고역이 죽는다.
스크립트가 준 값도 `F1 < F2 < …` 최소 간격이 구조적으로 강제된다(극이 겹치면
이득이 Qᵐ 으로 폭발한다).

### 난류 노이즈 / 치찰음
| 이름 | 뜻 |
|---|---|
| `noise_gain` / `noise_center` / `noise_bw` | 난류 소스의 세기·대역 |
| `noise_entry` | 협착 위치. 0=성문 … K=입술 … K+6=성도 완전 우회 |
| `noise_am` | 성문 개방기 동기 변조 깊이 (기식성) |
| `noise_rough` | 난류의 **느린** 세기 변동 (0 = 정상 히스, 1 = 거친 난류) |
| `sib_pole_f` / `sib_pole_bw` | 앞공동 공진 = **치찰음의 정체** |
| `sib_zero_f` / `sib_zero_bw` | 뒤공동 반공진 |
| `sib_tilt` | 치찰음 기울기 [dB/oct] |
| `sib_mix` | 치찰음 필터 적용량 0~1 |

### 음조가 들리면 안 된다 — 공진이 너무 뾰족하지 않게

지글거림(꼬리가 두꺼운 진폭 분포)을 잡고 나서도 /ㅅ/ 에서 **주기적인 소리**가
남았다. 원인을 가르는 결정적 실험: 출력의 **위상만 무작위로 돌려도** 같은 소리가
났다(울림 지표 0.455 → 0.455, 변화 없음). 즉 시간영역 아티팩트가 아니라
**스펙트럼이 뾰족해서** 나는 소리다. 잡음이 좁은 공진을 지나가면 그 공진에서
울리고, 귀는 그걸 음높이로 듣는다.

| | 1~11 kHz 스펙트럼 평탄도 |
|---|---|
| 사람의 /s/ (넓은 고원) | 0.2 ~ 0.4 |
| 이전 (극 Q=8.2) | **0.059** |
| 현재 | **0.15** |

고친 것 둘.

1. **치찰음 공진의 감쇠를 크게.** 극 대역폭 800 → 2200 Hz, 영점 900 → 2600 Hz.
   물리적으로도 이쪽이 맞다 — 앞공동은 짧고, 입술로 열려 있어 방사 손실이 크고,
   난류원이 한 점이 아니라 협착 하류에 퍼져 있다. 그래서 사람의 /s/ 는 뾰족한
   봉우리가 아니라 4~10 kHz 의 넓은 고원이다. (대역폭을 넓혀도 `sib_pole_f` 가
   피크 위치를 정하는 성질은 유지된다: 설정 3500/7000 → 피크 3961/7312 Hz.)
2. **`noise_bw_scale`** — 노이즈 경로에서만 포먼트 대역폭에 곱하는 배율(1~6,
   기본 3). 성문 펄스가 아니라 난류가 성도를 울릴 때는 감쇠가 훨씬 크다:
   여기소가 협착 하류에 퍼져 있어 공진이 뭉개지고, 마찰 구간에는 성문 폐쇄에
   의한 주기적 재여기도 없다. 유성음의 Q(F2 에서 25 까지)를 그대로 쓰면
   속삭임에 음조가 얹힌다.

**셋 다 학습 대상이다.** `sib_pole_bw`/`sib_zero_bw` 와 `noise_bw_scale` 은
인코더가 프레임마다 예측하고(범위 150~4000 Hz, 1~6배), 난류 소스의 스펙트럼
사전과 변조 스펙트럼은 `nn.Parameter` 다. 즉 "이 화자의 마찰음이 얼마나
뭉개져 있는가" 를 데이터가 직접 알려 준다.

### 실제 녹음에 맞춘 결과 (한국어 "스")

앞의 추측들을 실제 녹음 하나로 검증했더니 **삼각형 가설이 틀렸다**. 실측 스펙트럼에
모형을 경사하강으로 맞춰(rmse 2.25 dB) 나온 값:

| | 내가 추측한 값 | 실측에서 나온 값 |
|---|---|---|
| 저역 스커트 | +20~40 dB/oct (가파른 삼각형) | **+3.4** (거의 평평) |
| 고역 스커트 | −4 | **−13.5** (가파르다) |
| 봉우리의 주역 | 앞공동 극 | **앞니 공명 7.2 kHz** |
| 바닥 | 없음 | **피크 대비 −11 dB** |

세 가지를 배웠다.

1. **앞니 공명이 봉우리를 만든다.** 앞공동 극은 넓고(BW 3800) 낮은 곳(3.75 kHz)에
   있고, 6~8 kHz 의 봉우리는 좁은 앞니 공명이 만든다. 혀끝과 앞니 틈으로 얕게
   빠져나가는 제트의 휘파람 성분이다 (`sib_teeth_f` / `sib_teeth_bw`).
2. **스펙트럼이 전역적으로 깔린다.** 난류원은 앞공동 공진만 통해 나오는 게 아니라
   **입 구멍에서 그대로도 방사된다**(단극 방사). 이 병렬 경로를 `sib_floor_db`
   (피크 대비 dB)로 둔다. 없으면 봉우리 밖이 통째로 비어서 실제 녹음처럼 안 된다.
3. **삼각형이 아니라 넓은 고원 + 가파른 고역**이다.

결과: 실측 대비 평균 절대오차 15.6 dB → **5.0 dB** (600 Hz~11.5 kHz).

주의: 실측의 300 Hz 이하 성분(피크 대비 −10 dB)은 상당 부분 마이크 근접 호흡음과
실내 저역으로 보인다. `sib_floor_db` 를 올리면 거기까지 맞출 수 있지만, 다른
재생 환경에서 웅웅거릴 수 있다.

### 소리 크기 — 마찰음이 튀지 않게

실측하면 모음이 마찰음보다 **5.4 dB 크다**. 우리 모델은 +0.7 dB 였다(마찰음이
6 dB 큰 셈). 이러면 치찰음만 튀어나와 들린다.

`VoiceProfile.fricative_level_db` 가 그 비율이고, `score.fricative_gain` 이 실제
게인으로 바꾼다. 합성 경로를 바꾸면 `FRICATIVE_CAL_DB` 를 다시 재야 하는데,
`test_fricative_level_matches_profile` 이 드리프트를 잡는다.

파일로 저장할 때도 주의해야 한다. `save_wav` 의 기본 피크 정규화는 파일마다 다른
이득을 붙여 **파일 간 상대 레벨을 지운다**. 비교해 들을 때는 `target_rms=` 를 쓸 것.

### 페이드 인/아웃 — 치찰음 음량은 유량을 따라간다

마찰음의 세기는 협착부를 지나는 **부피속도(유량)** 로 정해진다. 협착이 형성되며
기류가 붙고, 해제되며 빠지므로, 실제 치찰음은 스위치처럼 '탁' 켜지지 않고 부드럽게
들고 난다. 예전 구현은 마찰음 진폭을 상수(`env = ones`)로 둬서 히스가 갑자기
켜졌다 꺼졌다 — 게이트를 연 것처럼 들렸다.

그래서 마찰음/음절 세그먼트에 유량 포락선을 넣을 수 있다.

```yaml
# '스' 를 유량이 천천히 붙었다 천천히 빠지게 (초 단위)
- {type: fricative, phone: s, dur: 0.9, fade_in: 0.28, fade_out: 0.30}

# 유량 곡선을 직접 지정 — 두 번 부풀었다 꺼지는 마찰음
- {type: fricative, phone: s, dur: 1.2,
   flow: [[0, 0], [0.2, 1], [0.5, 0.1], [0.8, 1], [1, 0]]}

# 음절 '사' — 마찰음이 유량과 함께 부드럽게 들어와 모음으로 넘어간다
- {type: syllable, onset: s, vowel: a, dur: 0.55, fade_in: 0.05}
```

세그먼트 손잡이:

* `fade_in`, `fade_out` — 유량 상승/하강 시간 [초]. raised-cosine 라 모서리가 없어
  전이에 클릭이 안 난다. 짧은 마찰음이라 둘이 안 들어가면 비례해서 줄인다.
* `flow` — `[[위치0~1, 값], ...]` 로 유량 포락선을 직접 지정(fade 를 대신한다).
* `flow_exp` — 유량→진폭 지수. 난류 파워는 유량에 초선형(∝ U^n, n≈2.5~3;
  Stevens/Shadle)이라 진폭은 U^(n/2) 로 는다. 그래서 유량을 그대로 음량으로 쓰지
  않고 이 곡률을 거치게 한다 — 낮은 유량에서 더 많이 죽어 시작이 부드러워진다.
  선형 램프로 음량을 직접 올리면 그 곡률이 사라져 '녹음을 페이드한 것' 처럼 들린다.

구현은 `aerodynamics.frication_flow`(유량 포락선)과 `flow_to_noise_amp`(유량→진폭)이고,
`test_sibilant_fade_shapes_the_flow_envelope` 등이 동작을 잠근다. 여성 화자 예제는
`examples/female_sibilant_fade.yaml`, 음원 생성은 `scripts/gen_female_sibilant.py`.

### 봉우리는 삼각형이어야 한다 — 극 하나로는 둥근 돔밖에 안 나온다

음조를 없애려고 극의 대역폭을 넓혔더니(BW 2200) 이번엔 **모양을 잃었다**.
2차 공명의 크기응답은 로렌치안이라 봉우리가 둥글고, 넓히면 그냥 돔이 된다.

| | 저역 스커트 | −6 dB 폭 |
|---|---|---|
| 사람 /s/ | +20~40 dB/oct | 0.6~1.0 옥타브 |
| 극 하나(돔) | **+7.7** | 0.57 |
| 스커트 도입 후 | **+44** | 0.42 |

핵심은 **가파름의 출처가 공진의 Q 가 아니라는 것**이다. 실제 마찰음의 가파른
저역 스커트는 협착-앞공동 계의 고역통과 성질 + 소스 스펙트럼 + 방사가 겹쳐
만든 것이라, 공진을 좁히지 않고도 만들 수 있다. 그래서 로그주파수의 조각별
직선으로 직접 준다(`filters.skirt_response`).

    dB(f) = slope_lo · log2(f/f_peak)   (봉우리 아래, 양수면 상승)
    dB(f) = slope_hi · log2(f/f_peak)   (봉우리 위, 음수면 하강)

공진이 아니므로 아무리 세워도 울리지 않는다 — 첨도 2.98 로 그대로다.
`sib_slope_lo` / `sib_slope_hi` 로 조종하고, 인코더도 예측한다.

주의: `zero_f` 와 `slope_lo` 는 둘 다 저역 스커트를 만들어서 서로 맞바꿔 가며
같은 모양을 낼 수 있다(부분적 축퇴). 추출한 프로파일에서 개별 값보다
**재현된 모양**을 믿어야 한다.

### 구강과 결합해야 한다 — 마찰음은 입 밖에서 나지 않는다

앞의 두 수정(감쇠, 느린 변조) 뒤에도 마찰음이 **쨍하게** 남았다. 원인은 두 가지,
둘 다 "노이즈가 구강을 거치지 않는다" 는 같은 뿌리다.

**1. 협착 뒤 공동으로의 결합이 0 이었다.** 마찰음 노이즈가 `noise_entry = K+6`
으로 성도를 **완전히 우회**하고 있었다(부분 캐스케이드가 병적이라 우회시켜
두었던 것인데, 물리적으로 틀렸다). 협착은 음향적으로 완전한 벽이 아니어서
난류음의 일부는 협착을 통해/돌아 뒤공동까지 닿았다가 성도 전체를 거쳐 나온다.

결합이 없으면 저·중역이 통째로 비고(1 kHz 가 피크 대비 −28 dB), 마찰음이 입
안에서 난 소리가 아니라 **위에 얹은 히스**처럼 들린다. 그리고 뒤따르는 모음이
무엇이든 똑같은 소리가 난다 — 동시조음이 없다.

`noise_back_leak`(0~1, 기본 0.25)이 그 경로다. 같은 난류원에 걸린 두 병렬
경로이므로 응답을 그냥 더하면 된다(선형).

    H_noise = (1 − leak)·[앞공동(치찰음 필터)] + leak·[성도 전체]

| | 1 kHz (피크 대비) | 동시조음 |
|---|---|---|
| leak = 0 | −27.8 dB | /사/ 와 /시/ 의 마찰음이 동일 |
| leak = 0.3 | −16.6 dB | /s/+/아/ −16.6 vs /s/+/이/ −26.6 dB |

**2. 난류 소스가 나이퀴스트까지 평평했다.** 이게 '쨍' 의 직접 원인이다.
실제 난류원은 평평하지 않다 — 협착부 제트의 에디에 특징적 크기가 있어 모서리
주파수(≈5 kHz) 위로 떨어지고(Stevens, Shadle 의 마찰음 소스 모형), 성도 벽의
점성·열 손실도 주파수를 따라 커진다. 그래서 `TurbulenceSource.log_prior` 의
초기값을 **5 kHz 위 −6 dB/oct** 로 두었다(백색 초기화가 아니라).

| | 8 kHz → 11 kHz | 무게중심 |
|---|---|---|
| 평평한 소스 | −2.1 dB (고원) | /s/ 8034, /ʃ/ 6546 Hz |
| −6 dB/oct | **−4.9 dB** | /s/ 7387, /ʃ/ 5736 Hz |

둘 다 학습 대상이다. `noise_back_leak` 은 인코더가 프레임마다 예측하고(0~0.6),
소스 사전은 `nn.Parameter` 라 초기값에서 데이터로 옮겨 간다.

### 지글거리면 안 된다 — 변조는 느린 성분만

`noise_rough` 를 **광대역**으로 두면 안 된다. 백색 소스 자체가 이미 빠른 난류
요동을 담고 있어서, 그 위에 광대역 곱셈 변조를 또 얹으면 같은 것을 두 번 세는
셈이다. 두 잡음 과정의 곱은 꼬리가 두꺼운(K-분포) 진폭 분포가 되고, 그게 귀에는
**지글거리는 소리**로 들린다.

측정으로 확인한 것 (진폭 첨도, 핑크 노이즈 = 2.97 이 기준선):

| | 첨도 | 포락선 CV |
|---|---|---|
| 핑크 노이즈 (기준) | 2.96 | 0.137 |
| 광대역 변조 (변조 에너지의 65%가 50 Hz 위) | **4.35** | 0.283 |
| 느린 변조로 제한 (현재) | **2.97** | 0.136 |

바꾼 것 세 가지.

1. **변조를 느린 대역으로 제한.** 꺾임 주파수 120 Hz → 8 Hz, 기울기 −6 → −12 dB/oct.
   빠른 요동은 소스가 이미 만든다.
2. **`1 + r·env` 를 0 에서 자르지 않는다.** 0.4% 의 샘플에서 포락선이 납작하게
   끊겨 그 자체가 딱딱 끊기는 소리를 만들었다. `exp(0.3·r·env)` 로 바꿔 항상 양수다.
   계수 0.3 은 손잡이를 끝까지(r=1) 올려도 첨도가 4.3 을 넘지 않고 게인이 0.46
   아래로 안 내려가도록 잡았다 — **이 손잡이의 어떤 값에서도 지글거림이 없다.**
3. **성문동기 AM 을 유성 여부로 게이트.** 성대가 안 떠는 소리(속삭임, 무성 마찰음)에
   AM 을 걸면 F0 로 노이즈를 써는 셈이라 없는 주기성이 생긴다.

기본값도 낮췄다: `roughness` 0.35 → 0.12.

**치찰음을 왜 따로 두는가.** 난류 스펙트럼을 자유로운 대역게인 40 차원으로만
두면, 학습 모델은 그 40 차원을 '이 화자의 /s/ 를 재현하는 어떤 벡터'로 외운다.
외운 벡터는 프레임마다 같은 값이 되기 쉽고, 결과적으로 마찰음이 **미세하게
주기적인 텍스처**로 들린다. 패턴을 인식하면 패턴을 반복하기 때문이다.

물리적으로 마찰음 스펙트럼을 결정하는 건 몇 개 안 된다: 협착 앞공동의 1/4 파장
공진(극), 뒤공동·설하공의 반공진(영점), 소스의 기울기. 이 **6 개 숫자**가
치찰음의 정체이고, 사람마다 다른 것도 정확히 이 숫자들이다(치열 간격, 혀끝 위치,
앞공동 길이). 그래서 (a) 화자 지문으로 추출할 수 있고, (b) 스크립트에서 직접
조종할 수 있고, (c) 남은 자유도가 좁아져 외워버리기 어렵다.

주기성 자체는 두 곳에서 따로 막는다.
* `noise_rough` — 난류의 **느린** 세기 변동(제트 사행, 조음 미세변동). 이게 없으면
  '테이프 히스' 같은 죽은 소리가 된다.
* `losses.periodicity_match_loss` — 예측과 목표의 프레임별 주기성을 맞춘다.
  유성 구간에서 낮으면 HNR 붕괴, 무성 구간에서 높으면 주기적 치찰음. 한 항이
  양쪽을 다 잡는다.

### 위상
| 이름 | 뜻 |
|---|---|
| `disp_freq` / `disp_radius` | **하모닉 위상차** 올패스 (소스) |
| (인코더) `allpass_freq/radius` | 성도 군지연 정형 |

같은 크기 스펙트럼을 가진 두 소리도 **하모닉 간 위상 관계**가 다르면 다르게
들린다. 성문 폐쇄가 날카로우면 모든 하모닉이 폐쇄 순간에 정렬되어 '단단하게',
정렬이 흐트러지면 같은 스펙트럼인데도 부드럽고 넓게 들린다. 화자 개성의 한 축이고,
크기 스펙트럼만 맞추는 모델이 놓치는 부분이다.

여기서 위상을 **자유롭게 예측하지는 않는다** — 자유 위상은 우리가 없애려던
phasiness 를 되돌린다. 대신 2차 올패스 체인의 위상응답을 하모닉 주파수에서 평가해
위상 오프셋으로 쓴다.

```
φ_k += Σ_s arg H_ap(k·f0 ; F_s, r_s)
```

크기응답이 정확히 1 이라 스펙트럼 포락선이 절대 변하지 않고(측정: 변화 0.5% 이내,
파형은 175% 변화), 최소위상·안정 구조라 물리적으로 실현 가능한 위상만 나오며,
파라미터가 (F_s, r_s) 몇 쌍뿐이라 실제 음성에서 역추정할 수 있다.

## 3.5 운율과 실시간 — LLM 붙이기

`timeline`(무엇을 말하나)과 `prosody`(어떻게 말하나)는 분리되어 있다. 문맥은
문장 하나가 아니라 대화 전체를 보고 결정되기 때문이다 — 길게 설명할 때는 호흡이
길어지고, 되묻거나 망설일 때는 속도와 억양이 통째로 바뀐다.

```yaml
prosody:
  rate: 1.1                                   # 조음 속도 배율
  pitch_shift: -1.0                           # 반음 이동
  pitch_range: 1.35                           # 억양 폭 (0.3 단조 ~ 2.0 과장)
  contour: [[0, 0], [0.35, 3.5], [1, -3.0]]   # [[위치, 반음], ...]
  declination: -2.0                           # 발화 전체 하강량(반음)
  breathiness: 0.1
  breath: {capacity_s: 3.5, depth: 0.45}      # 폐활량 -> 숨이 자동으로 들어간다
```

이 블록이 곧 **LLM 이 뱉을 작은 JSON** 이다. `ProsodyPlan.SCHEMA` 에 각 필드의
의미와 권장 범위가 문자열로 들어 있으니 프롬프트에 그대로 넣으면 된다.
피치는 로그(반음) 영역에서 다루므로 화자의 음역이 달라도 같은 억양이 같은
인상을 주고, 최종 F0 는 화자의 물리 음역으로 묶여 발산할 수 없다.

**호흡.** 사람은 폐활량이 있어서 길게 말하면 반드시 숨을 쉰다. 그 숨은 잡음이
아니라 발화 구조의 일부이고, 없는 것이 "AI 가 말한다" 는 인상의 큰 축이다.
`warp_timeline` 이 유성 발화 시간을 누적해 `capacity_s` 를 넘기 전에 들숨을
끼워 넣는다(문장 경계에서 우선, 모자라면 강제로).

### 실시간

매 순간의 상태가 **성문 순시위상 하나와 필터의 OLA 꼬리뿐**이라, 청크로 잘라
만들어도 한 번에 만든 것과 같은 결과가 나온다(측정: 청크 20~250 ms 에서 차이
−60 dB 이하, 들리지 않는다).

```python
st = StreamingSynth(cfg)
for ctrl_chunk in controller:      # 10 ms 프레임 단위로 파라미터를 바꿔 넣는다
    audio = st.step(ctrl_chunk)
```

| | |
|---|---|
| 지연 | LTV 필터 `ir_size/2` = 10.7 ms + 제어 보간 선행 1 프레임 10 ms = **약 21 ms** |
| 속도 | CPU 단일 스레드에서 **약 5x 실시간** (100 ms 청크) |

즉 파라미터를 프레임마다 바꿔 넣는 것이 곧 실시간 제어다 — 사람이 후두와 혀를
움직이는 것과 같은 방식으로. **다만 잔차망은 아직 이 경로에 없다.** 잔차망도
프레임 단위 LTV 필터라 원리적으로는 같은 방식으로 스트리밍되지만, 조건 입력에
목표 멜이 필요해서 (a) 코퍼스 학습 후 조건을 물리 출력만으로 바꾸거나
(b) TTS 음향모델이 예측한 멜을 쓰는 설계가 먼저 정리되어야 한다.

## 3.6 발성 시작은 압력이 만든다

`/사/` 처럼 기식에서 유성음으로 넘어갈 때, 바뀌는 건 입 모양만이 아니다.

1. 아직 열린 성문을 지나는 기류가 **난류 소음**(기식)을 낸다.
2. 성대가 내전하며 성문 틈이 좁아진다.
3. 성문하압 `Ps` 가 **발성 역치압(PTP)** 을 넘는 순간 자가진동이 시작된다.
   PTP 는 내전이 약할수록 높다 — 벌어져 있으면 더 세게 불어야 떤다.
4. 그 뒤로도 `Ps` 가 오르면서 **세기·F0·성문파 형상**이 함께 움직인다.

세기만 램프로 올리면(예전 구현) 시작이 '녹음을 페이드인한 것' 처럼 들린다.
F0 가 안 따라 오르고, 성문파가 기식→모달로 안 바뀌고, 기식 소음이 성대 진동과
무관하게 사라진다. `aerodynamics.py` 는 (Ps, 내전) 두 개에서 네 가지를
일관되게 끌어낸다.

    /사/ 의 실제 진행 (10 ms 프레임)
      t=  0ms  세기 0.000  F0 110.3  Rd 2.40  노이즈 주입 구강(11.8)
      t=280ms  세기 0.015  F0 116.0  Rd 2.22  주입 이동 중(9.2)
      t=320ms  세기 0.446  F0 119.6  Rd 1.24  성문쪽(2.7)
      t=400ms  세기 0.531  F0 119.7  Rd 1.20  기식 소멸

스크립트에서는 `pressure` / `adduction` 으로 직접 줄 수 있고, 주면 세기·F0·Rd·
기식이 전부 거기서 따라 나온다. Phase 5 의 '근육 좌표계' 로 가는 첫 단계다.

**한계**: 노이즈 경로가 하나뿐이라 구강 협착(마찰음)과 성문(기식) 두 소스를
동시에 낼 수 없다. 지금은 주입 위치를 옮기며 섞는다. 경로를 둘로 나누는 것은
남은 과제다.

## 3.7 성대를 여러 겹으로 — 하연과 상연

2질량 모델은 성대의 하연과 상연을 각각 한 점으로 본다. 자가진동과 수직 위상차는
나오지만 성문 통로의 **모양**은 두 점을 잇는 직선뿐이다. 실제로는 통로가 열릴 때
수렴형, 닫힐 때 발산형으로 바뀌고 그 형상 변화가 에너지 전달을 지배한다 —
점막파(mucosal wave)다.

`simulate_stack(params, n_masses=5)` 가 수직으로 n 겹 쌓은 모델이다.

| 겹 수 | F0 | 점막파 지연 | 하연/상연 진폭비 |
|---|---|---|---|
| 2 | 145 Hz | +0.71 ms (10% 주기) | 0.18 |
| 5 | 155 Hz | +0.46 ms (7%) | 0.30 |
| 7 | 155 Hz | +0.50 ms (8%) | 0.34 |

(사람: 0.5~1.5 ms, 하연이 앞선다. 양수 = 하연 선행.)

분할 규칙이 중요하다. n 조각으로 나누면 각 조각의 질량도 강성도 1/n 로 줄어야
ω=√(k/m) 가 n 과 무관하다. 처음에 질량을 n 배·강성을 1/n 배로 두었더니 F0 가
겹 수에 따라 130 → 45 Hz 로 흘렀다. 반대로 이웃 결합은 이산 라플라시안의 Δz² 를
상쇄해야 파동 속도가 유지되므로 n 에 비례해 커진다.

결합 강성(`coupling`, 기본 0.25)이 점막파의 크기를 정한다. 크면 전체가 한 덩어리로
움직여 파가 사라지고, 작으면 마디가 따로 놀아 비현실적으로 커진다.

## 4. 실제 녹음에서 뽑아내기

### 녹음 가이드

| 무엇을 재나 | 필요한 녹음 |
|---|---|
| 포먼트, Rd, 소스 tilt, 위상차 | 지속 모음 /아/ 를 편한 높이로 **3초 이상** |
| **파사지오**(성구 전환) | 낮은음 → 높은음 글리산도 2회 |
| 치찰음 지문 | /스ㅡ/ /슈/ 각 2초 |
| F0 분포, 지터/시머 | 보통 말하기 30초 이상 |

조용한 방에서 녹음할 것. 배경잡음은 그대로 '난류 노이즈'로 흡수된다.

```bash
python -m formant_ml.analysis.extract \
    --wav data/me/*.wav \
    --vowel-wav data/me/vowel_a.wav \
    --sibilant-wav data/me/s.wav \
    --glissando-wav data/me/gliss.wav \
    --out profiles/me.json --name me
```

역할별로 파일을 나눠 주는 게 중요하다. 안 나누면 모음·마찰음·글리산도가 한 통에
섞여 중앙값이 '이 화자의 값'이 아니라 '녹음 내용의 값'이 된다. 특히 파사지오는
F0 축 통계라서 다른 내용이 섞이면 엉뚱한 곳을 짚는다.

### 무엇을 어떻게 재는가

**성구와 파사지오.** 성대는 하나의 진동 방식만 갖지 않는다. 후두 근육의 균형이
바뀌면 진동하는 조직의 깊이가 바뀌고, 그 결과가 개방지수(H1-H2), 스펙트럼 기울기,
서브하모닉(SHR)에 나타난다. **파사지오는 이 지표들이 특정 F0 부근에서 급격히
꺾이는 지점**이다. 연속적으로 변하면 그냥 음역이고, 계단처럼 꺾이면 성구 전환이다.
그래서 "F0 에 대한 지표의 변화율이 국소 최대인 곳" 을 찾는 문제가 된다
(`registers.passaggio_candidates`).

**Rd(개방지수).** H1-H2 → Rd 대응표는 문헌의 회귀식을 베끼지 않고 **우리 LF 사전
자체**에서 만든다(`rd_h1h2_table`). 분석과 합성이 서로 어긋나지 않는다.

**Rd 와 tilt 는 함께 푼다.** 둘이 같은 관측량을 움직이기 때문이다. H1 과 H2 는
정확히 한 옥타브 차이라 tilt 를 t dB/oct 주면 H1-H2 가 정확히 t dB 줄어든다.
H1-H2 만 보고 Rd 를 읽으면 tilt 가 있는 화자는 무조건 pressed 쪽으로 치우친다
(참값 1.0 인데 0.71 로 측정됨). 반대로 입에서 잰 기울기(−9.7 dB/oct)를 그대로
소스 tilt 로 쓰면 성도 롤오프까지 두 번 세어 재앙적으로 어두워진다.
그래서 Rd 격자를 훑으며 tilt=0 프로브를 합성하고, 잔차를 `a + t·log₂(f/1kHz)`
로 회귀해 각 Rd 의 최적 tilt 를 닫힌 형태로 구한 뒤, 잔차가 가장 작은 Rd 를
고른다(`extract.fit_source_rd_tilt`).

**포먼트는 LPC 로 잰다.** 켑스트럼 포락선은 /아/ 의 F1(730)과 F2(1090)을 하나의
봉우리(≈880 Hz)로 뭉갠다. 그 값으로 프로브를 합성하면 성도 오차가 전부 소스
파라미터로 흘러 들어간다(측정: tilt 가 +2 대신 −10 으로 나왔다).

**위상차는 '모델이 이미 내는 위상'을 빼고 잰다.** 해석식(LF 위상 + 캐스케이드
위상)을 기준선으로 쓰면 LTV-FIR 절단/창가림 때문에 0.5 rad 쯤의 계통 오차가 남고,
그 오차를 위상차 파라미터가 흡수해 버린다. 같은 합성기로 프로브를 만들어 재면
모델 아티팩트가 전부 상쇄된다(`phase.model_reference_rps`). 이걸 하기 전 잔차
1.2 rad → 한 뒤 0.006 rad.

**치찰음은 경사하강으로 적합한다.** 우리 합성 모듈이 미분가능하니 역추정도 같은
코드로 한다(Vocal Tract Area Estimation by Gradient Descent 와 같은 발상).

## 4.5 학습 데이터는 얼마나 필요한가

제어 파라미터는 프레임당 **109 개**다(포먼트 36, 노이즈 43, 소스 6, 위상 14,
치찰음 6, 반공명 4). 신경 보코더가 프레임당 240 샘플을 만드는 것과 비교하면
2 배쯤 낮을 뿐이고, PLAN 에 적혀 있던 "≈60" 은 틀린 수치였다. 데이터가 덜 드는
이유는 **차원 수가 아니라 구조** 다 — 대부분이 시간축으로 매끄럽고, 물리 범위가
정해져 있고, 틀려도 사람 소리처럼 들린다.

| 단계 | 필요한 것 | 분량 |
|---|---|---|
| VoiceProfile 추출 | 지속모음 + 글리산도 + 치찰음 | **1~2 분** |
| Phase 1 복사합성 (인코더) | 깨끗한 단일화자 | **10~30 분**이면 쓸 만하고, 1 시간이면 넉넉 |
| Phase 2 표현력 (비음/파열음) | 음소 커버리지 있는 코퍼스 | 1~5 시간 |
| Phase 4 잔차망 | 위와 같은 데이터 | 1~5 시간 (모델 못 하는 것이 많을수록 더) |
| Phase 3 TTS (텍스트→제어) | 텍스트 정렬 코퍼스 | 5~20 시간 |

인코더는 프레임 단위 회귀기라 **시간보다 음소 커버리지**가 중요하다. 같은 문장을
10 시간 읽는 것보다 다양한 음소·음높이·세기를 30 분 담는 게 낫다.

### 1~10 초 조각을 짜깁기할 때

표준적인 방식이고 문제없다. 다만 네 가지를 지켜야 한다.

1. **같은 화자, 같은 마이크, 같은 방.** 녹음 조건이 섞이면 모델이 그 차이를
   난류 노이즈 경로로 흡수한다(PLAN §5). 이게 가장 흔한 실패다.
2. **레벨을 조각마다 정규화하지 말 것.** 이 레포는 이제 **파일 단위 RMS** 로
   맞춘다(예전에는 크롭마다 피크 정규화를 해서, 조용한 구간이 부풀려지고 모델이
   그 들쭉날쭉한 레벨을 성문 세기로 설명하려 들었다). 조각마다 이득을 다르게
   붙이면 화자의 다이내믹이 통째로 사라진다.
3. **앞뒤 무음을 100~200 ms 남길 것.** 자음의 시작·끝 전이가 거기 있다.
   딱 붙여 자르면 그 정보가 사라지고 파열음이 특히 망가진다.
4. **길이는 1~10 초면 충분.** 학습은 어차피 `--seconds`(기본 1.5 초)로 무작위
   크롭한다. 다만 조각이 크롭보다 짧으면 0 으로 패딩되므로, **최소 2 초**는
   되게 자르는 편이 낫다.

## 5. 어디까지 믿을 만한가

합성한 목소리를 추출해 되찾는 실험으로 측정한 값이다
(`tests/test_voice.py::test_extracted_profile_recovers_what_was_synthesized`).

| 항목 | 참값 | 추정 | 비고 |
|---|---|---|---|
| F0 중앙값 | 135 Hz | 135 Hz | |
| 포먼트 F1/F2/F3 | 730/1090/2440 | 686/1035/2494 | LPC, 6% 이내 |
| 치찰음 극 / 영점 | 7400 / 3100 Hz | 7387 / 3117 Hz | |
| 파사지오 | 224 Hz | 221 Hz | 글리산도 녹음 기준 |
| Rd | 1.00 | 1.10 | 열린 모음 기준 |
| 소스 tilt | +2.0 dB/oct | +4.1 dB/oct | **아직 ~2 dB/oct 오차** |
| 위상차 (1 stage) | 1800 Hz / r 0.85 | 1805 Hz / 0.849 | 잔차 0.006 rad |

**알려진 한계**

1. **Rd 는 열린 모음에서만 믿을 만하다.** H1-H2 는 F1 이 H2 근처인 모음(/이/ /우/)
   에서 낮게 나와 pressed 쪽으로 치우친다. 측정: 같은 Rd=1.2 인데
   /아/ 1.07, /에/ 1.00 은 잘 맞고 /이/ 0.63, /우/ 0.47 로 무너진다.
   H1*-H2* 성도 보정 코드는 있지만(`h1_h2_db(formant_f=...)`) **기본은 꺼져 있다** —
   보정에는 프레임별 F1/F2 가 정확해야 하는데, 그 정확도가 안 나오면 보정 안 한
   것보다 나빠진다. 제대로 하려면 LPC 기반 프레임별 포먼트 추적기가 필요하다.
2. **소스 tilt 에 ~2 dB/oct 오차가 남는다.** 프로브의 성도가 녹음의 성도와
   완전히 같지 않아서 그 차이가 기울기로 흘러든다.
3. **파사지오는 글리산도 녹음이 필요하다.** 일반 발화만 있으면 F0 축 통계가
   내용에 지배되어 엉뚱한 지점을 짚는다(측정: 224 Hz 를 276 Hz 로).
4. **성구 지표는 상관량이지 성문 직접 측정(EGG)이 아니다.** 절대값보다 **같은
   화자 안에서의 변화**가 훨씬 믿을 만하다.
5. **노이즈 경로의 부분 캐스케이드는 근사다.** 포먼트 캐스케이드에서 '협착 하류만'
   을 정확히 표현할 수 없어 peak 정규화로 조건수를 맞췄다. 도파관 모드
   (`tract: waveguide`)에서는 협착 하류 면적함수로 정확히 계산한다.
